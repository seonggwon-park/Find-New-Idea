## KQ1. Weight+activation quantization at serving time (W8A8 / W4A8 / W4A4): best results and failure modes

### Takeaway
W8A8 (SmoothQuant-style, INT8 or FP8) is effectively lossless and is what production stacks deploy; W4A8KV4 (QServe/QoQ) is the best *deployable* trade-off because it keeps GEMMs on INT8 tensor cores; W4A4 is still a research regime — FlatQuant (ICML 2025) is the strongest verified W4A4 result (LLaMA-3-70B zero-shot 79.01 vs 79.95 FP16) but its WikiText-2 perplexity is still +0.92 over FP16 and its *decode* speedup is <1x at small batch, and 2025–26 papers still describe massive-activation / down_proj outliers as "unresolved" in W4A4 PTQ.

### Cited Findings

**Baselines and the deployable frontier**
- SmoothQuant (arXiv 2211.10438, ICML 2023) (V): training-free W8A8 that "migrates part of the quantization difficulties from activation to weights" via a mathematically equivalent per-channel scaling (alpha 0.6–0.9 in the released eval); claims negligible loss on OPT-175B, BLOOM-176B, GLM-130B, MT-NLG 530B; up to 1.56x speedup and 2x memory; Llama-2-7B WikiText ppl 5.474 → 5.515; activation scales precomputed from 512 Pile sentences (static calibration). [LIM] (from Atom's critique, S) INT8 "cannot utilize lower bit arithmetic such as INT4 Tensor Cores" and does little for KV memory; in the lmquant comparison table SmoothQuant is evaluated with *per-tensor static* KV cache quantization — a weak KV baseline. — [Source](https://github.com/mit-han-lab/smoothquant); [lmquant table](https://github.com/mit-han-lab/lmquant)
- Atom (arXiv 2310.19102, MLSys 2024) (V/S): W4A4 with 128-element groups, channel reordering, mixed precision ("keeper" outlier channels at higher precision), dynamic activation quantization, KV-cache quantization and co-designed kernels; claims up to 7.73x end-to-end throughput vs FP16 and 2.53x vs INT8 "at the same latency target". [CRIT] efficiency measured on a single RTX 4090 only; accuracy from *simulated* quantization; README to-dos still include "release code to reproduce results" and "end-to-end throughput evaluation code"; batch sizes not stated in text. [LIM] MLSys-2024 slides (S) claim "KV cache is relatively easy to quant: simple 4-bit RTN maintains accuracy" — contradicted for Qwen-family models by 2026 work (see KQ4). — [Source](https://github.com/efeslab/Atom); [MLSys slides](https://mlsys.org/media/mlsys-2024/Slides/2655.pdf)
- QuaRot (arXiv 2404.00456, NeurIPS 2024) (V): Hadamard rotations applied to residual stream, FFN activations, attention and KV cache using computational invariance; "all weights, activations, and KV cache in 4 bits"; LLaMA2-70B loses at most 0.29 WikiText ppl and retains 99% zero-shot; no channels kept in higher precision. [CRIT] the 0.29 figure is for 70B with GPTQ weights; with RTN weights QuaRot W4A4 on LLaMA-3-70B gives ppl 55.44 (FlatQuant's table, V) and in the lmquant table QuaRot W4A4 gives Llama-3-8B 8.33 vs 6.14 FP16 and Llama-3.1-70B 5.97 vs 2.81 — i.e., >2x relative ppl on Llama-3 70B-class models. — [Source](https://github.com/spcl/QuaRot); [FlatQuant table](https://github.com/ruikangliu/FlatQuant); [lmquant](https://github.com/mit-han-lab/lmquant)
- SpinQuant (arXiv 2405.16406) (V): learns rotations by Cayley optimization because "random rotations produce high variance in quantized model accuracy". W4A4KV4 zero-shot averages (Float / SpinQuant / QuaRot): LLaMA-2 7B 66.9/64.0/62.5; 13B 68.3/66.9/66.2; 70B 72.9/71.2/70.3; LLaMA-3 8B 69.6/65.2/63.3; LLaMA-3 70B 74.5/69.3/65.1; SmoothQuant W4A4 = 39.0 (7B), LLM-QAT 44.9. [LIM] gaps remain 1.4–5.2 points; when GPTQ is used the rotation must be optimized for W16A4KV4 then applied to W4A4KV4; 70B requires FSDP optimization. — [Source](https://github.com/facebookresearch/SpinQuant)
- DuQuant (arXiv 2406.01721, NeurIPS 2024 Oral) (V/S): rotation + permutation to distribute both "massive" and "normal" outliers; authors report massive outliers appear in the FFN down_proj of recent LLMs; DuQuant++ (separate repo) targets MXFP4. [CRIT] README gives no numeric tables in text (figures only); no speed claims. — [Source](https://github.com/Hsu1023/DuQuant)
- FlatQuant (arXiv 2410.09426, ICML 2025) (V): learned per-layer affine (Kronecker-factored) transforms, "flatness" objective. W4A4 WikiText-2 ppl (FP16 / QuaRot-GPTQ / SpinQuant-GPTQ / FlatQuant-GPTQ): L2-7B 5.47/6.10/5.96/5.78; L2-13B 4.88/5.40/5.24/5.11; L2-70B 3.32/3.79/3.70/3.54; L3-8B 6.14/8.16/7.39/6.90; L3-70B 2.86/6.60/6.21/3.77. Zero-shot avg FlatQuant vs FP16: L3-70B 79.01 vs 79.95 (RTN weights), L3-8B 71.23 vs 73.23. Speed on one RTX 3090, LLaMA-2-7B, batch 1→64: prefill 2.12–2.30x, **decode 0.71–1.76x** (QuaRot 0.70–1.75x; plain Int4 0.81–1.83x). [LIM] "the last two layers of DeepSeek V3/R1 are hard to quantize" (flag `--v3_not_last`); vLLM integration is fake-quant only; decode at small batch is slower than FP16 because online transforms cost more than the memory saved. [CRIT] "<1% accuracy drop" is true for zero-shot but ppl is +32% relative on L3-70B. — [Source](https://github.com/ruikangliu/FlatQuant)
- QServe / QoQ (arXiv 2405.04532, MLSys 2025) (V/S): W4A8KV4. Progressive group quantization (weights INT8 first, then INT4 so all GEMMs run on INT8 tensor cores); SmoothAttention migrates key-quantization difficulty onto (unquantized) queries; compute-aware weight reordering + register-level parallelism to cut dequantization latency. Motivation (S): existing INT4 methods incur 20–90% runtime overhead dequantizing weights or partial sums, so "reducing bit precision does not necessarily speed up LLM inference". WikiText2 ppl (FP16 / QoQ W4A8KV4 / QoQ g128): Llama-3-8B 6.14/6.89/6.76; Llama-2-7B 5.47/5.75/5.70; Llama-2-70B 3.32/3.52/3.47; Mistral-7B 5.25/5.45/5.42; Llama-3.1-70B 2.81/3.68/3.51 (lmquant). Throughput vs best TensorRT-LLM baseline (input 1024, output 512, in-flight batching off, same memory budget): L40S 1.13x (Llama-2-7B) to 3.47x (Qwen-1.5-72B, 59 vs 17 tok/s); A100 1.17x (Llama-2-70B) to 2.38x (Qwen-1.5-72B). [CRIT] max-throughput batch sizes are 128/256 for 8B and 4/32 for 72B; the 3.47x L40S number is 59 tok/s absolute at batch 4 — a memory-capacity win on a 48 GB card, not a kernel win; Qwen accuracy not reported; DeepCompressor branch "deprecated". — [Source](https://github.com/mit-han-lab/omniserve); [paper](https://arxiv.org/abs/2405.04532)

**2025–2026 W4A4 developments (all S)**
- "Outlier Smoothing with Closed-Form Rotations for W4A4" (arXiv 2511.22316): states massive outliers (MO) and normal outliers (NO) "remain a major unresolved challenge in PTQ settings"; reports W4A4 zero-shot tables where DuQuant trails on LLaMA-2 7B/13B but is strongest on LLaMA-3 70B. — [Source](https://arxiv.org/abs/2511.22316)
- ReSpinQuant (arXiv 2604.11080, ICML 2026): layer-wise subspace-residual rotations; LLaMA-3 8B W4A4 ppl 7.24 vs QuaRot 7.82, SpinQuant 7.50. [CRIT] still +1.1 ppl over FP16 6.14; ppl-only in the snippet. — [Source](https://arxiv.org/abs/2604.11080)
- Block Rotation for MXFP4 (arXiv 2511.04214): "existing W4A4 methods are primarily designed for INT4", studies MXFP4 W4A4 with block rotations. — [Source](https://arxiv.org/abs/2511.04214)
- WUSH (Feb 2026; ID not retrieved): closed-form optimal linear blockwise transforms for joint W/A quantization (int and FP formats); argues fixed Hadamard is data-agnostic so "its optimality is unclear". — [Source via search summary](https://arxiv.org/abs/2511.04214)
- DFRot (arXiv 2412.00648): randomized Hadamard outperforms plain orthogonal transforms at W4A4 "but the reason remains unknown". — [Source](https://arxiv.org/abs/2412.00648)
- Other: ConvRot (2512.03673), OstQuant (2501.13987), OffQ "offsetting structured outliers" (2606.07116), KronQ (2607.07964), SERQ low-rank error reconstruction (2603.08185; notes FlatQuant "outperforms all compared models"). — [KronQ](https://arxiv.org/abs/2607.07964); [SERQ](https://arxiv.org/abs/2603.08185)

**Failure modes: BOS/massive activations, attention sinks, down_proj**
- "Measuring Maximum Activations in Open LLMs" (arXiv 2605.15572) (S): models route mass to a BOS or low-information token (attention sink); sink tokens have dimensions exceeding 1000 in Qwen3-235B; "outliers dominate the dynamic range during quantization". — [Source](https://arxiv.org/abs/2605.15572)
- "A Unified View of Attention and Residual Sinks" (arXiv 2601.22966) (S): massive activations caused by self-attention/softmax; a gated rescaling reduces W4A4 degradation to 1.2 points (training-side fix). — [Source](https://arxiv.org/abs/2601.22966)
- Softpick (arXiv 2504.20966) (S): quantized softpick models outperform softmax, especially at low bits (training-side). — [Source](https://arxiv.org/abs/2504.20966)
- IntactKV (arXiv 2403.01241) (S): keeps KV of "pivot tokens" (BOS etc.) in full precision to improve quantization. — [Source](https://arxiv.org/abs/2403.01241)
- DuQuant (V): massive outliers localized at FFN down_proj input in LLaMA-family models. — [Source](https://github.com/Hsu1023/DuQuant)
- Massive activations (Sun et al., arXiv 2402.17762) and attention sinks / StreamingLLM (arXiv 2309.17453) (M; IDs from memory) are the standard references for the mechanism.

**Prefill vs decode mixed precision (all S)**
- Mix-Quant (arXiv 2605.20315): NVFP4 prefill (16-element blocks, E4M3 block scales + tensor scale, RTN) and BF16 decode; ~3x prefill speedup "while largely preserving task accuracy"; argues prefill has quantization redundancy and decode does not. — [Source](https://arxiv.org/abs/2605.20315)
- PMPD (arXiv 2410.13461, ICLR 2025): phase-aware precision plus progressive lowering along the generated sequence; 1.4–12.2x linear-layer speedups. [CRIT] layer-level, not end-to-end, speedups. — [Source](https://www.arxiv.org/pdf/2410.13461)
- Recurrent Residual Quantization (arXiv 2608.04048): Qwen2.5-72B GSM8K: BF16 prefill + INT2 decode 0.9045 vs all-BF16 0.9037 vs all-INT2 0.8666 ("exploratory"). — [Source](https://arxiv.org/abs/2608.04048)
- Disaggregated Quantization (arXiv 2609.26333), FineServe (2509.06261), SUN/QSUN (2603.02599; quantize only the decode module and re-tune prefill), SpectrumKV (2606.08635; per-token FP16/INT8/INT4 for KV transfer between P and D workers; "Qwen2.5-7B fails under INT4 KV quantization"). — [SpectrumKV](https://arxiv.org/abs/2606.08635); [FineServe](https://arxiv.org/abs/2509.06261)

**Dynamic per-token activation quantization: cost (S)**
- Per-token scaling is argued to be *faster* than per-tensor on GPUs (row-wise reductions, no cross-block sync) and is "the standard in LLM-serving frameworks for INT8"; vLLM W8A8 default uses dynamic per-token activations. — [Quantamination](https://arxiv.org/abs/2604.26505); [CUDA quantization notes](https://cppcheatsheet.com/notes/cuda/cuda_quantization.html)
- LiquidGEMM (arXiv 2509.01229): existing W4A8 GEMM kernels "fall short in practice due to inefficient dequantization on CUDA Cores, which cannot keep pace with Tensor Cores". — [Source](https://arxiv.org/abs/2509.01229)
- AMD/Quark on Kimi-K2.5 (MI325X): W4A8 up to 16% lower TPOT and 18% higher throughput than W4A16 at low concurrency; W8A8 gives best per-token latency at low concurrency but ~2x the memory of W4A8. [CRIT] vendor blog. — [Source](https://rocm.blogs.amd.com/artificial-intelligence/kimi-k2.5-w4a8/README.html)
- Quantamination (arXiv 2604.26505): dynamic quantization "leaks your data across the batch" — a side-channel/privacy issue of batch-shared dynamic scales. — [Source](https://arxiv.org/abs/2604.26505)
- Kurtic et al., "Give Me BF16 or Give Me Death?" (ACL 2025; arXiv 2411.02355 (M)): large-scale study finding W8A8 FP8/INT8 near-lossless on Llama-3.1 (S, not read). — [Source](https://preview.aclanthology.org/setup/2025.acl-long.1304)

### Inferences
- The *best verified W4A4* today is FlatQuant-class learned transforms: zero-shot within ~1 point on 70B, but perplexity gaps of +0.3 (L2-70B) to +0.9 (L3-70B) remain and grow for Llama-3-generation models (larger vocab, more outlier-heavy), consistent with the SpinQuant table where Llama-3 gaps (4.4–5.2) are 2–3x the Llama-2 gaps.
- Nobody has demonstrated W4A4 *decode* speedups at realistic small batch: FlatQuant's own numbers are 0.71x at bs=1; QServe explicitly abandons A4 for A8 for this reason. W4A4 wins are prefill/compute-bound wins.
- Failure modes are consistent across papers: (i) massive activations at sink/BOS tokens in a handful of channels (down_proj input), (ii) RoPE-induced magnitude inconsistency in keys, (iii) Llama-3/Qwen-family being harder than Llama-2. The *remedies* diverge: rotations (random vs learned vs closed-form), pivot-token exemption (IntactKV), training-side sink removal (gated rescaling, softpick).
- Prefill-heavy quantization (NVFP4 prefill / BF16 decode) is a new consensus direction; the opposite split (high-precision prefill, INT2 decode) also shows anecdotal evidence — the two are not yet reconciled.

### Gaps
- No controlled study isolates *why* Llama-3/Qwen are harder at W4A4 (vocabulary size? q/k bias? RoPE base? sink count?) — all papers report it, none explains it.
- No paper measures the time cost of the per-token activation quantization pass itself as a fraction of W8A8/W4A8 GEMM time (search found claims of "basically free" but no profiler breakdown).
- DFRot states explicitly that randomized Hadamard outperforming structured orthogonal rotations at W4A4 is unexplained.
- Prefill/decode asymmetric precision has no theory of *why* decode is more sensitive (candidate: one token per step means no cross-token averaging of per-token scale error; untested).
- Could not fetch "Give Me BF16 or Give Me Death" to extract numbers.

## KQ2. KV-cache quantization: lowest safe bit-widths for keys vs values, why keys are harder, and what theory exists

### Takeaway
Consensus: keys need per-channel (or rotated/pre-RoPE) treatment because of persistent outlier channels and RoPE-induced channel mixing, while values tolerate per-token quantization; ~4-bit KV is near-lossless on most (not all) models, 2-bit is achievable with rotations plus sink protection (RotateKV: <0.3 ppl on LLaMA-2-13B) or with vector quantization (CommVQ, CQ ~1 bit/channel), but a "2-bit cliff" on multi-needle long-context retrieval is reported for KIVI/TurboQuant/PolarQuant (SPECTRA), and the strongest theory (QJL/TurboQuant unbiased inner-product estimators with distortion bounds) optimizes MSE / inner-product error rather than attention-output or token-level error.

### Cited Findings

**Foundational methods (2024)**
- KIVI (arXiv 2402.02750, ICML 2024) (V/S): keys per-channel, values per-token, 2-bit, tuning-free; keeps a `residual_length` of recent tokens in FP16 (32 in the GSM8K example); 2.6x lower peak memory, up to 4x batch, 2.35–3.47x throughput. Rationale (S): key cache has outlier channels so grouping along channels captures them; value cache "can only be quantized per-token because it is used to calculate the attention output" and per-token appends naturally in streaming. [LIM] (V) only 2/4-bit; flash-attention support "Beta" and prefill-only; LongBench support only Llama/Mistral. [CRIT] HF Transformers docs (V) warn that quantized cache "can harm latency if the context length is short"; quantized cache does not support sliding layers or torch.compile. — [Source](https://github.com/jy-yuan/KIVI); [HF docs](https://raw.githubusercontent.com/huggingface/transformers/main/docs/source/en/kv_cache.md); [paper](https://arxiv.org/abs/2402.02750)
- KVQuant (arXiv 2401.18079, NeurIPS 2024, v6 May 2025) (V/S): per-channel **pre-RoPE** key quantization (RoPE "rotates key channel pairs by position-dependent angles, producing inconsistent channel magnitudes"; quantizing pre-RoPE and applying RoPE after dequant in a fused kernel gives 0.82 ppl improvement for 3-bit LLaMA-7B), sensitivity-weighted non-uniform quantization (NUQ, Fisher information), dense-and-sparse outlier isolation with a capped number of outliers per token, attention-sink-aware (first ~5 KV in FP16); <0.1 ppl degradation at 3-bit on WikiText-2/C4; LLaMA-7B at 1M context on one A100-80GB and 10M on 8 GPUs. [LIM] (V) requires a Fisher-gradient pass per model; roadmap still lists "optimized kernels" and deployment code; [CRIT] the 1M/10M claims are *memory feasibility*, accuracy evaluated by ppl and passkey on 32K models. — [Source](https://github.com/SqueezeAILab/KVQuant); [paper](https://arxiv.org/abs/2401.18079)
- MiKV / "No Token Left Behind" (arXiv 2402.18096) (S): importance-aware mixed precision — keep would-be-evicted KV at low precision instead of dropping; argues eviction causes safety/hallucination/context-loss failures; mixed-precision groups run on weight-only kernels. — [Source](https://arxiv.org/abs/2402.18096)
- GEAR (arXiv 2403.05527) (V/S): ultra-low-bit quantization + low-rank residual + sparse outlier matrix; "near-lossless" 4-bit; up to 2.38x throughput, 2.29x peak-memory reduction; does *not* keep first/last tokens uncompressed. [LIM] (V) "research quality" code; low-rank correction cost at decode not quantified on the page. — [Source](https://github.com/opengear-project/GEAR); [paper](https://arxiv.org/abs/2403.05527)
- QAQ (arXiv 2403.04643) (S): separate non-uniform strategies for K and V (different sensitivities), outlier handling, attention-aware; up to 10x compression claimed. — [Source](https://arxiv.org/abs/2403.04643)
- CQ, "KV Cache is 1 Bit Per Channel" (arXiv 2405.03917, NeurIPS 2024) (S): couples contiguous channels into a shared vector code (e.g., CQ-4c8b) exploiting channel interdependence; maintains quality at ~1 bit/channel; 1.4–3.5x throughput (secondary summary). — [Source](https://arxiv.org/abs/2405.03917)
- SKVQ (arXiv 2405.06219, COLM 2024) (V/S): channel reorder + clipped dynamic quantization + sliding window of recent tokens kept high precision + 5 sink tokens, pre-RoPE option; paper claims 2-bit K / 1.5-bit V. [LIM] (V, authors) results used fake quantization; dequant/GEMV kernel "naive and inefficient"; clipping ratio (0.91–0.97) "can significantly affect perplexity" and was changed to avoid overfitting. — [Source](https://github.com/cat538/SKVQ)
- ZipCache (arXiv 2405.14256, NeurIPS 2024) (S): channel-separable token-wise quantization, normalized attention-score saliency, per-token bit allocation; Mistral-7B GSM8K 4.98x compression with −0.38% accuracy; in Line-Retrieval all quantization methods beat H2O eviction. — [Source](https://arxiv.org/abs/2405.14256)
- QJL (arXiv 2406.03482, AAAI 2025) (V/S): JL transform followed by a 1-bit sign quantizer on keys; no quantization constants stored (saving the 1–2 bits/number that per-group scales cost). [THEORY] applying QJL to the key and an *unquantized* JL transform to the query gives an **unbiased estimator of the inner product** with "provably minimal relative distortion on attention scores" (assumptions: Gaussian/random projection; distortion scales with projection dimension — released config uses 256 projected bits, 512 for initial layers; values 2-bit, group 32, 128-token FP16 buffer). Overall "3 bits per float". [LIM] README gives no ppl/NIAH numbers; [CRIT] the vLLM TurboQuant implementation docs report "community consensus (5+ independent groups)" that the QJL component "hurts attention quality by amplifying variance through softmax" — a direct contradiction of the unbiasedness-implies-harmless narrative. — [Source](https://github.com/amirzandieh/QJL); [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/34773); [vLLM TurboQuant docs](https://docs.vllm.ai/en/latest/api/vllm/model_executor/layers/quantization/turboquant/)

**Rotation / transform-based 2-bit methods (2025–26)**
- RotateKV (arXiv 2501.16383) (V/S): outlier-aware rotation with channel reordering (keeps FWHT), **pre-RoPE grouped-head rotation**, attention-sink-aware quantization using massive activations to locate sinks without attention scores; 2-bit LLaMA-2-13B <0.3 WikiText-2 ppl degradation, GSM8K <1.7% degradation; NIAH retained at 40K (S). Key observation (S): "inconsistency in the magnitudes of channel-wise outliers significantly undermines the effectiveness of outlier-aware rotation". [LIM] (V) simulation/fake quant only, no kernels. — [Source](https://github.com/ZunhaiSu/RotateKV); [paper](https://arxiv.org/abs/2501.16383)
- PolarQuant (Google; arXiv 2502.02617) (S): random preconditioning → polar coordinates → quantize angles, which are concentrated enough that per-block normalization constants can be dropped; ~4.2x KV compression; in their runtime test (16K prompt + 1K gen) KIVI generated *slower* than the exact baseline while SnapKV/PyramidKV were faster but lower quality. — [Source](https://arxiv.org/abs/2502.02617)
- PolarQuant (Wu et al.; arXiv 2502.00527, NeurIPS 2025) (S): keys only; outliers live in one of the two dimensions that RoPE rotates together, so group keys into 2-D sub-vectors and store radius+angle; decoding q·k as table lookup. — [Source](https://arxiv.org/abs/2502.00527)
- KVTuner (arXiv 2502.04420, ICML 2025) (V/S): offline layer-wise K/V precision pairs (e.g., K8V4); finding: "key cache is generally more important than value cache for quantization error reduction"; critiques online fine-grained decisions as high-overhead. [LIM] results not on README. — [Source](https://github.com/cmd2001/KVTuner); [paper](https://arxiv.org/abs/2502.04420)
- TurboQuant (Zandieh et al.; arXiv 2504.19874, ICLR 2026) (S + V via third-party implementations): random (Hadamard) rotation → per-coordinate Lloyd-Max scalar quantization with b−1 bits → 1-bit QJL residual for an unbiased inner-product estimator; claims ~3.5 bits/value near-zero loss and training-free 3-bit KV (S). [THEORY] (via OCTOPUS 2605.21226 summary, S) after a random orthogonal rotation each coordinate of a unit vector is marginally symmetric-Beta on [−1,1], so the MSE-optimal scalar codebook depends only on d and b — "near-optimal distortion" is w.r.t. this per-coordinate MSE model. Community audit (0xSero/turboquant, V): 3-bit keys / 2-bit values; key cos-sim 1.000 but **value cos-sim 0.940 at 2-bit** ("value quantization is the main quality bottleneck"); Recall@8 0.55 and recall@1 38% at 3-bit (N=4096); RTX 5090 30K-context prefill +5.7%, decode +3.1% ("within noise"); honest compression 4.41x at head_dim 256 vs "5.1x" claim; hybrid decode dequantizes all history to fp32 each step (storage savings, no compute savings). vLLM's implementation (docs, S) *omits QJL* and uses uniform quantization for values. — [paper](https://arxiv.org/abs/2504.19874); [community impl](https://github.com/0xSero/turboquant); [vLLM docs](https://docs.vllm.ai/en/latest/api/vllm/model_executor/layers/quantization/turboquant/)
- CommVQ (arXiv 2506.18879, ICML 2025) (V/S): additive learned codebook that **commutes with RoPE** so codes can be decoded inside attention; 2-bit "nearly lossless" (87.5% size reduction), 1-bit "minimal loss"; LLaMA-3.1-8B 128K context on one RTX 4090 (S). [LIM] (V) four-step offline codebook training (collect KV, scaling, train key codebook, train value codebook); real-memory Triton kernels exist only for LLaMA-3.1-8B at 1-bit. — [Source](https://github.com/UMass-Embodied-AGI/CommVQ)
- KVSink (arXiv 2508.04257) (S): attention sinks occur beyond the first N tokens (e.g., token 14 in LLaMA2-7B prefill), so Preserve-First-N misses them; predicts sink positions from fixed-layer/channel activation outliers via top-k (no attention scores needed, FlashAttention-compatible); improves KVQuant ppl and reduces reliance on 16-bit outliers. — [Source](https://arxiv.org/abs/2508.04257)
- XQuant (arXiv 2508.10395) (S): cache quantized layer inputs X and rematerialize K,V (immediate 2x vs KV since one tensor); 7.7x memory savings <0.1 ppl; XQuant-CL (cross-layer deltas) 10x at 0.01 ppl, 12.5x at 0.1 ppl; evaluated on MHA/GQA, not MLA. [CRIT] trades memory for extra GEMMs per decode step; ppl-only in snippet. — [Source](https://arxiv.org/abs/2508.10395)
- KVLinC (arXiv 2510.05373) (S): finds "quantizing raw keys channel-wise and quantizing Hadamard-rotated values token-wise achieves best performance"; adds linear correction adapters; RULER only at 4K/8K. — [Source](https://arxiv.org/abs/2510.05373)
- PatternKV (arXiv 2510.05176, ICML 2026) (S): pattern-aligned residual quantizer; 4-bit −0.08% avg vs FP16; consistent 2-bit gains; +10% test-time-scaling accuracy; 1.5x throughput (v1 said 1.4x), 1.25x batch. — [Source](https://arxiv.org/abs/2510.05176)
- MixKVQ (arXiv 2512.19206, ACL 2026) (S): query-aware selection of critical key channels for higher precision (weighs intrinsic channel quantization difficulty and relevance to the query), per-token values; ~2.3–2.7 effective bits near-BF16 on reasoning (third-party numbers). — [Source](https://arxiv.org/abs/2512.19206)
- PM-KVQ (arXiv 2505.18610, ICLR 2026) (V/S): progressive bit-width reduction per block, block-wise sensitivity allocation, positional-interpolation calibration; up to 8% reasoning gain at equal memory for 7B–70B long-CoT models. — [Source](https://github.com/thu-nics/PM-KVQ); [ICLR](https://proceedings.iclr.cc/paper_files/paper/2026/hash/afb8caec018d3c8f6ef8b81fa52386fe-Abstract-Conference.html)
- KVarN (Huawei; arXiv 2606.03458; vLLM fork) (V): per-128-token tile: Hadamard rotation → Sinkhorn-like iterative variance normalization (alternating column/row std normalization in log space) → asymmetric RTN with per-channel key scales and per-token value scales; preset k4v2_g128; calibration-free. Benchmarks (self-reported): Qwen3-32B AIME25 at 16K matches FP16 accuracy, exceeds FP16 throughput, ~4x KV capacity; GLM-4.7-Flash (MLA) 0.94x throughput, 2.77x capacity, AIME25 53.3% both; headline "3–5x capacity, up to ~1.3x FP16 throughput, up to ~2.4x TurboQuant throughput at same capacity". [LIM] fork pinned to vLLM 0.23; compute in fp16; block size 64/128 only; MLA throughput below bf16. — [Source](https://github.com/huawei-csl/KVarN)
- SPECTRA (arXiv 2608.07915) (S): "pushing the KV cache beyond the 2-bit cliff via spectral transform coding"; reports near-perfect single-needle where 2-bit KIVI/TurboQuant/PolarQuant start to fail and sharp multi-needle degradation of those baselines at long contexts. — [Source](https://arxiv.org/abs/2608.07915)
- Attention-aware transforms (S): OSCAR (arXiv 2605.17757) — quantization noise on channel j propagates to logits with weight λ_j = query energy along j; real query covariance is sharply anisotropic, so query-agnostic rotations are suboptimal for attention scores. "Spend Bits Where Queries Look" (arXiv 2608.04074) — Hadamard rotations *equalize variance* rather than compacting energy; derives closed-form key transforms from calibration statistics under a high-resolution model targeting attention-product distortion. — [OSCAR](https://arxiv.org/abs/2605.17757); [Spend Bits](https://www.alphaxiv.org/abs/2608.04074.md)
- Other 2026 (S): RaBitQCache (arXiv 2606.31519; rotated binary quantization, RULER 8K–64K on LLaMA-3.1-8B); Hurwitz-quaternion multiplicative quantization (2605.27646; "naive int4 collapses on all three RULER subtasks" for Qwen3-8B at 4K/8K); D-Quant driftable entropy coding (2609.19880); RDKV rate-distortion joint eviction+quantization (2605.08317, 4K–128K); KV-COBRA bit-rank co-allocation (2609.24298); VarRate (2607.15498); QEvict recoverable quantized eviction (2608.05326); AnTKV anchor-token sub-bit VQ (2506.19505); outlier-token tracing (2505.10938); "When Quantization Is Free" int4 KV faster than fp16 on Apple Silicon with 12.5x reduction of Qwen's 4-bit per-token ppl blow-up (2605.05699); INT8 KV GPU kernels (2601.04719); adaptive on-device bit allocation (2604.04722, CVPR 2026). — [RaBitQCache](https://arxiv.org/abs/2606.31519); [Hurwitz](https://arxiv.org/abs/2605.27646); [RDKV](https://arxiv.org/abs/2605.08317); [Apple int4](https://arxiv.org/abs/2605.05699)

**What production stacks actually ship (V)**
- vLLM: `kv_cache_dtype` fp8_e4m3 / fp8_e5m2; **default scales are all 1.0** (uncalibrated) unless llm-compressor scales are supplied; per-tensor or per-head (`k/v_scale=[num_kv_heads]`, FlashAttention backend only); sliding-window layers "more sensitive" (`--kv-cache-dtype-skip-layers`); with the FA3 backend attention compute itself is FP8 (queries also quantized). — [Source](https://raw.githubusercontent.com/vllm-project/vllm/main/docs/features/quantization/quantized_kvcache.md)
- llm-compressor KV example: static per-tensor symmetric FP8 K/V scales from 512 ultrachat samples; the only reported number is GSM8K 5-shot Llama-3-8B-Instruct 0.7748 with **no BF16 baseline shown** [CRIT]; notes quantized models "can be sensitive to the BOS token". — [Source](https://raw.githubusercontent.com/vllm-project/llm-compressor/main/examples/quantization_kv_cache/README.md)
- TensorRT-LLM: FP8 KV on Ampere+; NVFP4 KV only from an offline ModelOpt checkpoint and currently only paired with FP8 W/A; NVFP4 on Blackwell (sm100/103/120) and Rubin (sm107) only. — [Source](https://raw.githubusercontent.com/NVIDIA/TensorRT-LLM/main/docs/source/features/quantization.md)
- HF Transformers QuantizedCache: quanto int2/int4, HQQ int2/4/8; axis settings; warns of latency harm at short context. — [Source](https://raw.githubusercontent.com/huggingface/transformers/main/docs/source/en/kv_cache.md)

**Why keys are harder (synthesis of cited claims)**
- Outlier channels in keys (KIVI, KVQuant) make per-token scaling waste range; values have no such channel structure (KIVI, S).
- RoPE mixes channel pairs by position-dependent angles → magnitude inconsistency across positions (KVQuant 0.82 ppl gain from pre-RoPE; RotateKV pre-RoPE grouped rotation; CommVQ RoPE-commuting codebook; PolarQuant-Wu 2-D pairs). Low-index (low-frequency? — snippet says "low-numbered") RoPE channels contribute the majority of quantization noise (KV-Latent, arXiv 2507.11273, S); Q-ROAR (arXiv 2510.00028) searches per-frequency-band scales on K/Q weights. — [KV-Latent](https://arxiv.org/abs/2507.11273); [Q-ROAR](https://arxiv.org/abs/2510.00028)
- Key error enters the softmax exponent (multiplicative e^{±2η} effect, SpectrumKV, S) while value error enters a convex combination and is bounded by the per-token reconstruction error independent of sequence length (Runtime-Certified Bounded-Error Quantized Attention, arXiv 2605.20868, S). — [SpectrumKV](https://arxiv.org/abs/2606.08635); [Runtime-certified](https://arxiv.org/abs/2605.20868)
- Empirical priority: KVTuner, MixKVQ, KVarN (k4v2), KVLinC all allocate more bits to keys — *but* TurboQuant's community audit finds values the bottleneck at 2-bit under scalar Lloyd-Max. The two are consistent only if "keys harder *per bit at 4-bit*" and "values harder *at 2-bit with scalar codes*" — an untested hypothesis.

### Inferences
- Lowest "negligible-loss" widths with current evidence: K≈2-bit requires rotation + sink protection (RotateKV) or VQ (CommVQ, CQ); V≈2-bit works with per-token scalar (KIVI) at the cost of retrieval degradation at long contexts; 1-bit anything (KIVI-1bit) collapses retrieval (SpeCache). "Negligible" is almost always defined on ppl/GSM8K/LongBench, not on multi-needle or long-CoT.
- Theory is at the level of inner-product/MSE distortion (QJL, TurboQuant, RaBitQ-style) — no paper bounds *token-level* or *task-level* error, and the one documented community finding (QJL hurts) suggests unbiased logits are not the right objective because softmax is convex in logits (Jensen: E[softmax(s+ε)] ≠ softmax(s)).
- Pre-RoPE quantization and RoPE-commuting codebooks are two ways to the same end; the latter avoids a RoPE kernel at decode but needs training.
- Serving reality: most 2-bit KV papers release fake-quant code (SKVQ, RotateKV, KVTuner); only KIVI, KVQuant, QServe, CommVQ (1-bit), KVarN, TurboQuant (vLLM) have real kernels, and third-party measurements show throughput gains "within noise" unless batch is enlarged.

### Gaps
- No controlled comparison of per-channel scaling vs Hadamard rotation vs learned/covariance-aware (KLT-style) transforms for keys *as a function of head-dim statistics* (channel kurtosis, cross-channel correlation, query covariance). OSCAR/Spend-Bits argue covariance-aware wins; TurboQuant argues data-agnostic is near-optimal; both are self-reported.
- No theory for *why QJL/TurboQuant's unbiased residual hurts* in practice (variance amplification through softmax is asserted in vLLM docs, not proven).
- Values at ≤2 bits: whether per-token scalar quantization is fundamentally worse than VQ (CQ/CommVQ) at equal bits is not isolated.
- Could not read TurboQuant's or QJL's theorems; distortion constants, dependence on d, and norm-storage overhead are unverified.
- No paper quantifies the KV-cache *metadata* overhead (scales/zeros/norms) in bits/element across methods on a common footing — "3-bit" vs "3.5-bit" vs "2.3–2.7 effective bits" are not comparable.

## KQ3. Attention-computation quantization kernels (FA3-FP8, SageAttention 1/2/2++/3, INT8 attention) — trade-offs and softmax-sensitivity theory

### Takeaway
INT8 QK^T with K-smoothing (SageAttention) and FP8 with block scaling + incoherent processing (FlashAttention-3) are the accepted "safe" points (2–3x over FA2, ~1.2–1.3 PFLOPS FP8 on H100); INT4 QK^T (SageAttention2) and FP4 microscaling (SageAttention3, 1038 TOPS on RTX 5090) are shown mainly on diffusion/video models and the authors themselves recommend SageAttention2 over 3 for precision-sensitive use; LLM-side accuracy evidence is thin (naive INT8 attention collapses Llama2 MMLU to 25.5%; a competitor table shows SageAttention −0.95 LongBench on Llama-3.1-8B with a large SAMSum drop), and softmax-sensitivity theory consists of first-order Jacobian and e^{±2η} multiplicative bounds with no tight canonical theorem.

### Cited Findings
- FlashAttention-3 (arXiv 2407.08608, NeurIPS 2024) (S/V): FP8 via block quantization + incoherent processing (multiply Q,K by a random-sign Hadamard per head, O(d log d)); "2.6x more accurate than standard attention with per-tensor quantization in cases with outlier features" — [CRIT] measured on synthetic Q,K,V ~ N(0,1) with 0.1% entries scaled up; FP8 reaches ~1.2 (v1) / 1.3 (NeurIPS) PFLOPs/s, BF16 840 TFLOPs/s (85% utilization). Released hopper code (V): **FP8 forward only**, beta; README does not mention descale factors or whether incoherent processing is in the shipped kernel. — [paper](https://arxiv.org/abs/2407.08608); [repo](https://github.com/Dao-AILab/flash-attention); [blog](https://tridao.me/blog/2024/flash3/)
- SageAttention (arXiv 2410.02367, ICLR 2025) (V/S): INT8 QK^T with smoothing of K (remove per-channel mean) and FP16/FP8 PV with two-level accumulation; motivation: naive INT8 attention drops Llama2 MMLU to 25.5% (random); repo: on RTX 5090 560 TOPS, 2.7x FA2; on Hopper "matches FA3-FP8 speed with better accuracy"; CogVideoX1.5-5B on H20: FA2 25'34", FA3 17'32", FA3-FP8 12'14", SageAttention 12'07". [CRIT] TOPS charts "exclude quantization and smoothing overhead"; end-to-end accuracy tables are images; "Not all models work with F.scaled_dot_product_attention = sageattn". — [Source](https://github.com/thu-ml/SageAttention); [paper](https://arxiv.org/abs/2410.02367)
- SageAttention2 (arXiv 2411.10958, ICML 2025) (S): per-thread INT4 Q/K with **Q smoothing** (not K), FP8 P̃/V at thread granularity with FP32-accumulate two-level strategy; ~3x FA2, ~4.5x xformers OPS. [LIM] wording of the PV fix changed across arXiv versions (v3 "FP32 matmul buffer"). — [Source](https://arxiv.org/abs/2411.10958)
- SageAttention2++ (arXiv 2505.21136) (S/V): FP8 PV using the FP16-accumulate FP8 instruction (2x faster than FP32-accumulate), narrowing P/V ranges to avoid FP16 overflow; 3.9x over FlashAttention with "same accuracy as SageAttention2"; released 2025-07-01. — [Source](https://arxiv.org/abs/2505.21136)
- SageAttention3 (arXiv 2505.11594, NeurIPS 2025 Spotlight, v3 Jan 2026) (S/V): FP4 microscaling (1×16 groups) for both matmuls on Blackwell FP4 tensor cores; attention map P gets two-level quantization (per-token normalization, then FP4 microscaling) because FP4 has only 16 representable values; 1038 TOPS on RTX 5090, 5x the fastest FlashAttention on that GPU; SageBwd 8-bit trainable attention is lossless for fine-tuning but "not suitable for pretraining". Repo (V): released 2025-09-27 (`sageattention3_blackwell`), gated via HF form; **"recommends SageAttention2 over SageAttention3 for precision-sensitive applications"**. [CRIT] evaluation dominated by video/image generation; LLM results sparse; consumer Blackwell (sm120) only in the release. — [Source](https://arxiv.org/abs/2505.11594); [repo](https://github.com/thu-ml/SageAttention); [NeurIPS](https://papers.neurips.cc/paper_files/paper/2025/hash/4db397e0f760cc573c681e81a01a3dba-Abstract-Conference.html)
- HyQuant (arXiv 2608.27875) (S): hybrid-precision attention; its LongBench table for Llama-3.1-8B-Instruct: FA2 46.63 vs SageAttention 45.68, with SAMSum 12.48 → 6.87. [CRIT] competitor-reported. — [Source](https://arxiv.org/abs/2608.27875)
- RotateAttention (arXiv 2607.02584) (S): RoPE-aware rotation + range rectification for INT4 attention in video generation; observes Q and K have symmetric, comparable outlier patterns after RoPE so the transform must preserve their balance. — [Source](https://arxiv.org/abs/2607.02584)
- "Faster Than Flash" (arXiv 2609.00097) (S): 2-bit key scanning for sparse long-context decode; [THEORY] score error = projection of q onto quantization noise, scaling ∝ √d; probability of exceeding a safety margin decays with head dimension. — [Source](https://arxiv.org/abs/2609.00097)
- INT-FlashAttention (arXiv 2409.16997) (M; not found in search): INT8 Q/K/V FlashAttention for Ampere.

**Softmax-sensitivity theory (all S)**
- Jacobian-guided Noise Injection (arXiv 2608.20988, ICML 2026, Amazon): softmax is "a bottleneck for quantization stability due to its sensitivity to outliers and state-dependent Jacobian"; [THEORY] first-order bound on attention-weight change via operator norm of J = diag(p) − pp^T; suppressing ||J|| bounds quantization-induced degradation; method injects zero-mean Gaussian noise into pre-attention logits during training with variance from ||J||_F; up to 40% relative ppl improvement at low bits. [LIM] training-time method; first-order. — [Source](https://arxiv.org/abs/2608.20988)
- SpectrumKV (arXiv 2606.08635): [THEORY] if each logit moves by ≤ η, softmax probabilities change by a factor in [e^{−2η}, e^{2η}] (authors call it loose; shows low-entropy attention is risky because a small η on the dominant logit is a large absolute shift). — [Source](https://arxiv.org/abs/2606.08635)
- QAM-W (arXiv 2605.26339): local KL ≈ quadratic form in logit perturbation + cubic remainder (weight-side). — [Source](https://arxiv.org/abs/2605.26339)
- Runtime-Certified Bounded-Error Quantized Attention (arXiv 2605.20868): [THEORY] two-term per-head/per-step decomposition: key-quantization → attention-distribution distortion; value-quantization → output error ≤ per-token reconstruction error (convex combination), independent of sequence length; bounds computed online drive adaptive precision and fallback to FP16 originals held in host RAM (INT8 K / INT4 V on GPU). [LIM] "certification is local to each head and step; does not guarantee end-to-end correctness"; LLaMA-3.1-8B up to 128K on PG-19/NIAH/RULER. — [Source](https://arxiv.org/abs/2605.20868)
- "Pricing the Risk of Runtime Compression" (arXiv 2608.15810): anytime-valid admission tests and a "served-output law" for compressed serving state. — [Source](https://arxiv.org/abs/2608.15810)

### Inferences
- The attention-kernel literature optimizes TOPS on diffusion workloads where P is dense and sequence lengths are ~10^4–10^5 with full causal masks absent; LLM decode attention is memory-bound and gains nothing from INT4/FP4 *compute* unless the KV is also stored in that format — which is exactly the regime (FP4 KV + FP4 attention) that TensorRT-LLM gates behind ModelOpt and FlashMLA only ships for DeepSeek V4.1.
- Smoothing K (SageAttention 1) and smoothing Q (SageAttention2) are both mean-subtraction tricks that exploit the softmax shift-invariance along the token axis (subtracting a channel-mean of K changes all logits of a query by a constant) — a cheap, exact invariance that KV-cache methods rarely exploit explicitly (inference; not stated as such in sources).
- No source relates quantized-logit error to *attention entropy* formally; the available bounds imply opposite intuitions: the multiplicative bound says peaked (low-entropy) attention has large absolute shifts, the Jacobian bound (||J|| ≤ max p_i(1−p_i)) says peaked attention is locally *insensitive*. Reconciling these (second-order / tail-event analysis) is open.

### Gaps
- No LLM-centric accuracy study of SageAttention/FA3-FP8 across reasoning and long-context tasks (only one competitor table found).
- Whether FA3's incoherent processing is in the released kernel, and its cost at decode (Hadamard per step on Q and on cached K), is undocumented.
- No published softmax-sensitivity theorem that is tight for heavy-tailed logits or that uses attention entropy/sparsity as a parameter.
- SageAttention3 FP4 on LLM text generation (not DiT) — no numbers found.

## KQ4. Long-context-specific issues: error accumulation, retrieval, RoPE-frequency outliers, 1M-context results

### Takeaway
Quantization beats eviction on needle-style retrieval because every token survives, but (i) 1-bit KIVI collapses retrieval (SpeCache), (ii) a "2-bit cliff" on multi-needle long-context tasks is reported for KIVI/TurboQuant/PolarQuant (SPECTRA), (iii) even int4 per-token KV collapses on Qwen2.5/Qwen3 (SpectrumKV, Hurwitz, Apple-silicon paper), (iv) errors compound over long decodes in reasoning (MixKVQ, PM-KVQ, KVarN) because most methods were evaluated in prefill-like settings, and (v) despite "10M context" headlines, the longest *accuracy* evaluations of quantized KV found are RULER at 64K–128K — no 1M RULER result exists.

### Cited Findings
- SpeCache (arXiv 2503.16163) (S): under 1-bit KIVI, Mistral-7B and LLaMA-3-8B long-context retrieval is "significantly compromised"; speculative 16-bit prefetch restores near-FP16 accuracy. — [Source](https://arxiv.org/abs/2503.16163)
- SPECTRA (arXiv 2608.07915) (S): 2-bit KIVI/TurboQuant/PolarQuant "degrade sharply, especially at long contexts on multi-needle tests". — [Source](https://arxiv.org/abs/2608.07915)
- Hurwitz-quaternion KV (arXiv 2605.27646) (S): "naive int4 collapses on all three [RULER] subtasks" for Qwen3-8B at both 4K and 8K. SpectrumKV (2606.08635) (S): "INT4 tolerance varies by model; Qwen2.5-7B fails under INT4 KV quantization". Apple-silicon int4 KV (2605.05699) (S): a fused kernel reduces Qwen's 4-bit per-token perplexity blow-up by 12.5x. — [Hurwitz](https://arxiv.org/abs/2605.27646); [SpectrumKV](https://arxiv.org/abs/2606.08635); [Apple](https://arxiv.org/abs/2605.05699)
- "KV Cache Compression, But What Must We Give in Return?" (arXiv 2407.01527) (S): quantization (FlexGen, KIVI) "performs decently across all tasks" because no token is dropped; trade-off: quantized memory still grows with sequence length. — [Source](https://arxiv.org/abs/2407.01527)
- "Benchmarking KV-Cache Optimizations across Task Quality and System Performance" (Agrawal & Mayer, arXiv 2607.05399) (S): KIVI, TurboQuant (quantization), SnapKV (eviction), CaM (merging) on LongBench-style tasks with Llama-3.1-8B-Instruct and Mistral-7B-Instruct-v0.3; "compression ratio alone does not predict end-to-end performance"; measures TTFT, throughput, memory. — [Source](https://www.alphaxiv.org/abs/2607.05399)
- ZipCache (2405.14256) (S): every quantization method beats H2O on Line Retrieval. CAKE (2503.12491) (S): KIVI-INT4 + CAKE eviction beats KIVI-INT2 at matched storage. ReST-KV (2605.08840) (S): its eviction + 4-bit at 6.25% budget keeps accuracy while 2-bit KIVI/KVQuant on the full cache "drops noticeably". KVarN (2606.03458) (S): SnapKV/PyramidKV/KVZip compress only the prompt cache; quantization compresses both prefill and generation. "Taming the Fragility of KV Cache Eviction" (2510.13334) (S). — [CAKE](https://arxiv.org/abs/2503.12491); [ReST-KV](https://arxiv.org/abs/2605.08840); [Fragility](https://arxiv.org/abs/2510.13334)
- Error accumulation (S): MixKVQ (2512.19206) — error accumulates along depth and sequence; one corrupted value can break a math chain; PM-KVQ (ICLR 2026) — "existing methods quantize the KV cache at every decoding step" causing cumulative error, plus a calibration mismatch because short calibration data under RoPE misses rarely-active key channels; KVarN (2606.03458) — current methods are "evaluated in prefill-like settings" while decode errors "accumulate across timesteps, mainly from incorrect token scales". — [MixKVQ](https://arxiv.org/abs/2512.19206); [PM-KVQ](https://arxiv.org/abs/2505.18610); [KVarN](https://arxiv.org/abs/2606.03458)
- RoPE-frequency structure (S): KV-Latent (2507.11273) — the low-numbered RoPE channels contribute most of the noise; Q-ROAR (2510.00028) — groups RoPE dims into frequency bands with per-band K/Q weight scales, and notes YaRN/LongRoPE-style dimension-wise scaling limits "quantization-induced logit noise drift"; RoPE-aligned Q/K rotations for dynamic 4-bit quantization (2608.13365); RotateKV — pre-RoPE rotation because RoPE "interferes" with rotation. — [KV-Latent](https://arxiv.org/abs/2507.11273); [Q-ROAR](https://arxiv.org/abs/2510.00028); [RoPE-aligned](https://arxiv.org/abs/2608.13365)
- Longest evaluations found: KVQuant passkey on 32K models (memory feasibility to 1M/10M) (V/S); RDKV 4K–128K (S); Runtime-certified up to 128K (S); RaBitQCache RULER 8K–64K (S); KVLinC RULER 4K/8K (S); KVarN 16K AIME (V). — [KVQuant](https://arxiv.org/abs/2401.18079); [RDKV](https://arxiv.org/abs/2605.08317)
- Runtime (S): PolarQuant's test (16K + 1K gen) — KIVI slower than exact; SnapKV/PyramidKV faster but lower quality. — [Source](https://arxiv.org/abs/2502.02617)

### Inferences
- The "which is safer: eviction or quantization" question has no stable answer because papers compare at different budgets (6.25% vs 25%), different tasks (retrieval vs summarization) and are all self-reported; the only neutral benchmark (2607.05399) says ratio alone is not predictive.
- Qwen-family fragility at int4 is the clearest *model-dependence* signal; a plausible cause is the q/k/v bias terms in Qwen2.5 producing large constant key offsets (hypothesis — not stated in any source found).
- Decode-time error compounding is a distinct failure mode from prefill quantization error and is only addressed by progressive (PM-KVQ), variance-normalized (KVarN) or query-aware (MixKVQ) schemes from 2025–26.

### Gaps
- No RULER/NIAH evaluation of any quantized KV scheme at ≥256K, let alone 1M, despite memory-feasibility claims.
- No study of "lost in the middle" positional bias under quantized KV (zero hits).
- No mechanistic explanation of Qwen int4-KV collapse.
- Error-accumulation theory over T decode steps (does error grow as √T, T, or saturate?) is absent; KVarN's "incorrect token scales" diagnosis is empirical.

## KQ5. MLA (DeepSeek-V2/V3/V4), FP8/FP4 latent KV, and GQA/MQA sensitivity

### Takeaway
DeepSeek ships FP8 (and for V4.1, FP4) latent-KV formats in FlashMLA with per-32/16-element micro-scales; third-party work (SnapMLA) argues the decoupled RoPE part is numerically heterogeneous and should stay high precision — which FlashMLA's V4.1 format contradicts by quantizing the 64 RoPE dims too; the only GQA-vs-MLA sensitivity datapoint is a single 2026 preprint (+2.8% vs +3.0% ppl at 4 bits), and FP8-KV gives smaller relative savings on MLA because the latent is already ~1/10 of MHA KV.

### Cited Findings
- FlashMLA (DeepSeek) (V): current (2026-09-30 release, Hopper support removed) FP8 KV for DeepSeek-V4.1 (head_dim 512): **528 B/token** = 512 e4m3 values + 16 e8m0 scales (one per 32 values); FP4 **288 B/token** = 512 e2m1 values + 32 e4m3 scales (one per 16 values), valid only for `extra_k_cache`; "the 64 RoPE dimensions are quantized as well, so there is no bfloat16 part". B200 (CUDA 13.3): sparse prefill up to 1350 TFLOPS, sparse decode 1024 TFLOPS; fused norm/RoPE/attention/cast 1460/950; Ascend 950 prefill 410 TFLOPS (95% peak). No accuracy numbers. Earlier V3.2 FP8 format (S, secondary): 656 B/token with e4m3 values + fp32 scales, dequantized to bf16, **RoPE part not quantized** "for accuracy". — [Source](https://github.com/deepseek-ai/FlashMLA); [V3.2 summary](https://gittrend.io/repo/deepseek-ai/FlashMLA)
- SnapMLA (Meituan; arXiv 2602.10718) (S): FP8 MLA decoding faces "numerical heterogeneity from decoupling positional embeddings" and "scale misalignment in FP8 PV GEMM"; keeps the positional part in high precision with per-token quantization; up to 1.91x throughput with "negligible" degradation on long-context math/code. — [Source](https://arxiv.org/abs/2602.10718)
- "Agent Memory Below the Prompt: Persistent Q4 KV cache" (arXiv 2603.04428) (S): 4-bit KV ppl increase ≈ +2.8% Llama-3.1 (GQA) vs +3.0% DeepSeek (MLA); authors hypothesize the latent "has less redundancy to absorb 4-bit rounding error" and note asymmetric K=192/V=128 dims. [CRIT] single preprint, tiny difference. — [Source](https://arxiv.org/abs/2603.04428)
- KVarN on GLM-4.7-Flash (MLA) (V): parity on AIME25 (53.3%), 2.77x capacity, 0.94x throughput — the only verified MLA low-bit (k4v2) datapoint. — [Source](https://github.com/huawei-csl/KVarN)
- SGLang docs (S): W8A8 FP8 + FP8 KV cache + a batched-matmul operator for FP8 MLA with weight absorption; official DeepSeek-V3 weights are already FP8 ("do not pass --quantization fp8"). — [Source](https://docs.sglang.ai/references/deepseek.html)
- Vultr guide (S, low authority): FP8 KV benefit for DeepSeek V3.2 "limited because MLA already compresses the cache". — [Source](https://docs.vultr.com/inference-cookbook/cuda/model-guides/deepseek-v32)
- "Insights into DeepSeek-V3" (arXiv 2505.09343) (S): KV pairs stored in low-bit representations with "minimal impact on model performance" — no numbers. — [Source](https://arxiv.org/abs/2505.09343)
- vLLM per-head scales `k/v_scale=[num_kv_heads]` (V) — GQA groups share one scale per KV head. — [Source](https://raw.githubusercontent.com/vllm-project/vllm/main/docs/features/quantization/quantized_kvcache.md)
- XQuant (S) evaluates MHA and GQA but not MLA. — [Source](https://arxiv.org/abs/2508.10395)

### Inferences
- In weight-absorbed MLA decode, the latent c_kv is multiplied by W_UK before (or after absorption into) the query; quantization error in the latent is therefore projected through a *learned, anisotropic* matrix shared across heads — the per-channel-outlier intuition from MHA keys does not transfer directly, and no paper analyses this.
- The FlashMLA V3.2→V4.1 change (RoPE part bf16 → quantized) suggests DeepSeek found micro-scaled FP8 adequate for k_pe, contradicting SnapMLA's recommendation; one of the two is model- or scale-granularity-specific.
- GQA shrinks KV by the group ratio, so the *marginal* benefit of KV quantization is smaller, but no paper reports that GQA keys are intrinsically harder/easier to quantize.

### Gaps
- No controlled MHA vs GQA vs MLA study of KV-quantization sensitivity at equal bits.
- No accuracy table for FlashMLA FP8/FP4 formats.
- No theory of latent-space quantization under weight absorption (error propagation through W_UK, W_UV, and the RoPE-decoupled branch).

## KQ6. MoE serving quantization: expert-wise mixed precision, routing sensitivity, frequency-aware allocation

### Takeaway
MoE quantization work is overwhelmingly *weight-only*: experts are robust to 2–3-bit weights (MoQE, QMoE 0.8 bits/param on 1.6T SwitchTransformer), shared experts and routers need higher precision (QuantMoE-Bench; routers are ~0.04% of params so kept BF16), and per-expert bit allocation uses either activation frequency/routing weights (MC-MoE, BitsMoE, DynaExq) or Hessian sensitivity (MoPEQ explicitly rejects frequency); activation/KV quantization specific to MoE serving and routing-flip rates under quantized activations are essentially unstudied.

### Cited Findings
- MoQE (Microsoft; arXiv 2310.02410) (S): expert weights only to 2-bit; "expert layers are much more robust to quantization than conventional FFN layers"; 79.6% size reduction vs fp16 MoE, 1.24x speedup on A100. — [Source](https://arxiv.org/abs/2310.02410)
- QMoE (Frantar & Alistarh; arXiv 2310.16795, MLSys 2024) (S): SwitchTransformer-c2048 (1.6T) to <160 GB (20x, 0.8 bits/param) in <1 day on one GPU; <5% runtime overhead vs idealized uncompressed; [LIM] future work: other MoE models; focused on base-model compression. — [Source](https://arxiv.org/abs/2310.16795)
- QuantMoE-Bench (arXiv 2406.08155, v2 Feb 2025) (S): structure-aware mixed precision across blocks/experts/linears; "consistently activated shared experts potentially need higher precision"; best setup 65.35% vs GPTQ 64.30%. — [Source](https://arxiv.org/abs/2406.08155)
- MC-MoE (arXiv 2410.06270) (S): Pre-Loading Mixed-precision Quantization allocates per-expert bits from reconstruction error, routing weights and activation frequency; Online Dynamic Pruning of experts for unimportant tokens; 2.54 bits, 76.6% compression, 3.8% average accuracy loss. — [Source](https://arxiv.org/abs/2410.06270)
- MoPEQ (arXiv 2509.02512) (S): per-expert bits by **Hessian-trace sensitivity rather than activation frequency**; 2/3/4-bit on DeepSeek-VL2, MolmoE. — [Source](https://arxiv.org/abs/2509.02512)
- DynaExq (arXiv 2511.15015, v3 Feb 2026) (S): runtime system keeping hot experts at higher precision under a fixed single-GPU budget; argues static offline bit assignment "cannot adapt to shifting activation patterns"; Qwen3-30B/80B up to +4.03 points over static low-precision baselines. — [Source](https://arxiv.org/abs/2511.15015)
- GEMQ (arXiv 2605.23078) (S): global expert-level mixed precision on DeepSeekV2-Lite, Qwen1.5-MoE, Qwen3-30B-A3B (128 experts, top-8, 3.3B active), Mixtral-8x7B; routers ≈0.04% of parameters. — [Source](https://arxiv.org/abs/2605.23078)
- BitsMoE (arXiv 2606.00079) (S): spectral-energy + activation-guided bit allocation; ablations show routing weights and activation-based importance each help; 8-bit shared basis on W8A16 kernels. — [Source](https://arxiv.org/abs/2606.00079)
- EAC-MoE (ACL 2025) (S): quantization + Expert-Selection-Frequency pruning; Mixtral-8x7B memory 4.92x reduction, fits RTX 3090. — [Source](https://preview.aclanthology.org/ingestion-acl-25/2025.acl-long.633.pdf)
- "Less is MoE" (arXiv 2606.05538) (S): AWQ W4A16 g128 baseline skips router layers (mlp.gate). — [Source](https://arxiv.org/abs/2606.05538)
- Serving practice: DeepSeek-V3 natively FP8 (SGLang, S); AMD Quark W4A8/W8A8 on Kimi-K2.5 (S, vendor); Nota AI notes DeepSeek-style sigmoid routing vs softmax (S). — [AMD](https://rocm.blogs.amd.com/artificial-intelligence/kimi-k2.5-w4a8/README.html)
- TurboQuant community audit (V): on an 8x RTX 3090 MoE deployment, KV compression saved 30.9% of total KV vs ~77% on a pure dense transformer because hybrid/non-attention state is not compressible. — [Source](https://github.com/0xSero/turboquant)

### Inferences
- Frequency-aware and Hessian-aware bit allocation give conflicting prescriptions (MC-MoE/BitsMoE/DynaExq vs MoPEQ); frequency is a *serving* statistic (shifts with workload), Hessian is *calibration-set* bound — no paper measures the stability of either across domains.
- MoE decode at small batch is even more memory-bound than dense (each expert sees few tokens), so weight-only W4 wins; at large batch, per-expert activation quantization (dynamic per-token FP8/INT8 with grouped GEMM) is what DeepSeek-style FP8 serving does — but outside DeepSeek's own FP8 recipe, no public study of W4A8/W4A4 *activation* quantization on MoE experts, nor of router-decision flips caused by quantized hidden states, was found.

### Gaps
- Routing sensitivity: no measurement of top-k expert-selection flip rate under W8A8/W4A8 activations, nor its downstream effect.
- No MoE-specific KV-cache quantization study (MoE changes nothing in attention, but the memory budget split between resident experts and KV does).
- Expert-frequency-aware *dynamic* precision (DynaExq) has one paper; no theory of the precision/eviction trade-off for cold experts.
- Could not retrieve QuantMoE-Bench or MC-MoE full tables.

## KQ7. Speculative decoding + quantization: quantized drafts, self-speculation with quantized layers/KV, exactness

### Takeaway
Quantized self-speculation (QSpec W4A4 draft / W4A16 verify sharing weights and KV; QuantSpec hierarchical INT4/INT8 KV draft) reaches 1.6–2.5x with >90% acceptance; direct-cast MXFP4 drafts (ML-SpecQD) give 2–2.7x without training; "lossless" guarantees hold only with respect to the *quantized verifier's* distribution, no paper measures acceptance rate as a function of draft bit-width, and quantization and speculation compete for the same memory-bound slack (SpecDec-meets-Quantization, "Lossless but Not Free").

### Cited Findings
- QSpec (arXiv 2410.11305) (S): same model in two quantization modes — W4A4 drafts, W4A16 verifies; shares weights and KV cache (no extra memory); up to 1.64x throughput over W4A16 and recovers most W4A4 quality loss on multi-step reasoning (MATH). [THEORY] output distribution equals that of the W4A16 verifier (not FP16). — [Source](https://arxiv.org/abs/2410.11305)
- QuantSpec (Apple; arXiv 2502.10424, ICML 2025) (S): self-speculative draft = target architecture with 4-bit weights and a *hierarchical* 4-bit KV cache (INT4 ↔ INT8 switching without an extra cache copy); acceptance >90%; end-to-end up to ~2.5x; ~1.3x lower memory than sparse-KV self-speculation baselines; motivated by long-context edge inference. — [Source](https://arxiv.org/abs/2502.10424); [PMLR](https://proceedings.mlr.press/v267/tiwari25b.html)
- ML-SpecQD (Intel; arXiv 2503.13565) (S): MXFP4 draft obtained by direct-casting the BF16 target (no training/alignment) → up to 2x over BF16; adding a smaller draft for the MXFP4 draft (multi-level) → up to 2.72x. — [Source](https://arxiv.org/abs/2503.13565)
- "Speculative Decoding Meets Quantization" (arXiv 2505.22179) (S): evaluates EAGLE-2 with W8A8/W4A16/W4A8 targets; proposes a hierarchical framework where a small model converts tree drafts into sequence drafts; 2.78x for 4-bit Llama-3-70B on A100. — [Source](https://arxiv.org/abs/2505.22179)
- Quasar (arXiv 2603.01399) (S, secondary overview): claims a W8A8 verifier "maintains relative logit rankings, allowing rejection sampling to preserve generation quality identical to full-precision"; Qwen3 at T=0 mean acceptance length 1.40 vs 1.33 n-gram baseline. [CRIT] "identical to full precision" cannot follow from rejection sampling against a quantized target. — [Source](https://www.alphaxiv.org/overview/2603.01399)
- "Lossless but Not Free" (arXiv 2607.17283) (S): on Apple silicon the quantized Metal backend executes "parallel" verification serially; best 1.61x at K=6; 3 of 5 configurations slowed down. — [Source](https://www.alphaxiv.org/abs/2607.17283.md)
- Hierarchical Speculative Decoding (arXiv 2601.05724, ICLR 2026 oral) (S): provably lossless verification, +12% over EAGLE-3; "Revisiting Lossy Verification" (2607.26627) (S) catalogs methods that relax the reference distribution. — [HSD](https://arxiv.org/abs/2601.05724); [Lossy](https://arxiv.org/abs/2607.26627)
- KVarN (V) is compatible with MTP and DFlash speculative decoding and with AWQ INT4 weights (validated on Qwen3.6-27B) — the only verified "quantized KV + spec-dec" production datapoint. — [Source](https://github.com/huawei-csl/KVarN)

### Inferences
- Exactness: standard speculative sampling is exact w.r.t. the verifier's distribution p_q; if the verifier is quantized, outputs are exactly distributed as the quantized model — "lossless" is relative. For a *shared* KV cache (QSpec/QuantSpec), if the verifier reads the quantized KV, the verifier itself is a KV-quantized model; if it reads INT8/FP16 KV, two KV representations must coexist (QuantSpec's hierarchical trick).
- Acceptance rate vs draft bit-width should be monotone in draft/target KL; nobody has published the curve, so the optimal draft precision (W4? W2? MXFP4?) is unknown.
- Quantization and speculation both convert memory-bound slack into tokens; W4A16 targets become compute-bound during verification earlier, so speculation speedups shrink as weight precision drops (2505.22179's framing).

### Gaps
- No measured acceptance-rate curve vs draft bit-width or vs KV bit-width.
- No analysis of verifier KV quantization's effect on the *exact* output distribution (bias of quantized-KV p_q vs p).
- Could not fetch QSpec/QuantSpec/ML-SpecQD full texts for limitations sections.

## KQ8. Hardware/system: Blackwell FP4/FP8, dynamic-quant overhead, fused dequant & LUT kernels, memory- vs compute-bound regimes, eviction vs quantization

### Takeaway
Weight-only kernels (Marlin) stay near 4x only up to batch 16–32 and LUT kernels (FLUTE) are Ampere-tuned and below uniform-kernel peaks; INT4 activations pay 20–90% dequant/partial-sum overhead (QServe) so deployable stacks pick W4A8 or W8A8 on INT8/FP8 tensor cores and NVFP4 only on Blackwell; KV quantization typically yields *capacity* (batch) gains rather than latency gains (HF docs, PolarQuant runtime, TurboQuant +3% within noise, KVarN 0.94x on MLA), and the eviction-vs-quantization comparison has no neutral leaderboard.

### Cited Findings
- Marlin (IST-DASLab) (V): FP16×INT4 kernel with "close to ideal (4x) speedups up to batchsizes of 16–32 tokens" (prior kernels only at 1–2 tokens); theoretical max 3.87x at g128 (0.125 bits of scale overhead); argument: FLOP/byte ratios of 100–200 permit ~25–50 MACs per 4-bit weight while staying memory-bound; requires locked clocks to reproduce; "not yet optimized for Hopper"; Llama2-7B ppl 5.12 → 5.27 (INT4 GPTQ). — [Source](https://github.com/IST-DASLab/marlin)
- FLUTE (arXiv 2407.10960, EMNLP 2024) (S/V): LUT dequant fused GEMM, 2–4x over existing GEMM at batch <32, g128; 1.5–2x end-to-end on LLaMA-3; [LIM] optimized for Ampere, degrades at larger batch, "still falls short of the peak performance that kernels specialized for uniformly quantized matrices can achieve" on A100; (V) shape-specialized tiles, bf16 slower than fp16, numerical instability at W4G256 on A100; H100 unoptimized. — [paper](https://arxiv.org/abs/2407.10960); [repo](https://github.com/HanGuo97/flute)
- LUT-GEMM (arXiv 2206.09557) (M): earlier LUT-based weight-only GEMM.
- QServe (S/V): INT4 methods incur 20–90% runtime overhead from dequantizing weights or partial sums; QoQ keeps GEMM on INT8 TCs; throughput gains measured at batch 128–256 (8B) and 4–32 (72B) with in-flight batching off. — [Source](https://github.com/mit-han-lab/omniserve)
- LiquidGEMM (arXiv 2509.01229) (S): W4A8 dequant on CUDA cores is the bottleneck vs tensor-core throughput. — [Source](https://arxiv.org/abs/2509.01229)
- FlatQuant (V): decode speedup 0.71x at bs=1 → 1.76x at bs=64 on RTX 3090 (online transforms cost). — [Source](https://github.com/ruikangliu/FlatQuant)
- TensorRT-LLM (V): FP4 and FP8 on Blackwell/Hopper; NVFP4 on sm100/103/120 + Rubin sm107; MXFP4 Blackwell/Rubin only; FP8 block-scaling on sm100 uses an MXFP8-style recipe with different scale formats than SM90; FP8 KV on Ampere+; NVFP4 KV needs ModelOpt and only with FP8 W/A. — [Source](https://raw.githubusercontent.com/NVIDIA/TensorRT-LLM/main/docs/source/features/quantization.md)
- NVIDIA "Pushing Intelligence to 4-bit" (S): NVFP4 uses a scale per 16 values (finer than MXFP4's 32) for better accuracy, requires Blackwell. MixFP4 (arXiv 2605.31035) (S): adaptive FP4/INT4 block representations within NVFP4. — [NVIDIA](https://research.nvidia.com/labs/eai/blogs/pushing-intelligence-to-4-bit/); [MixFP4](https://arxiv.org/abs/2605.31035)
- SageAttention3 1038 TOPS on RTX 5090 (consumer Blackwell) (S); FlashMLA FP4 KV on B200 (V). — see KQ3/KQ5.
- KV-quantization latency reality (V/S): HF QuantizedCache "can harm latency if the context length is short"; TurboQuant community: +5.7% prefill / +3.1% decode at 30K "within noise"; hybrid path dequantizes to fp32 each step; KVarN 0.94x on MLA model; PolarQuant: KIVI slower than exact; KIVI's 2.35–3.47x comes from 4x larger batch. — [HF](https://raw.githubusercontent.com/huggingface/transformers/main/docs/source/en/kv_cache.md); [TurboQuant impl](https://github.com/0xSero/turboquant); [KVarN](https://github.com/huawei-csl/KVarN)
- Eviction vs quantization: NVIDIA KVPress (V) lists ~30 eviction/scoring presses (SnapKV, Expected Attention, KnormPress, StreamingLLM, TOVA, PyramidKV, KVzip, DuoAttention...) and supports quantization only via HF QuantizedCache (quanto 4-bit); leaderboard reports RULER at 4K; **no eviction-vs-quantization comparison**. — [Source](https://github.com/NVIDIA/kvpress)
- Dynamic quantization privacy (S): Quantamination (arXiv 2604.26505) — batch-shared dynamic scales leak data across requests. — [Source](https://arxiv.org/abs/2604.26505)
- Vendor cost claims (S, unverified): a learning-site article cites SemiAnalysis "~7x cheaper on GB200 + TRT-LLM/Dynamo vs H100 + vLLM" — not relied upon. — [Source](https://learn.traeai.com/t/ai-engineering/phases/17-infrastructure-and-production/07-tensorrt-llm-blackwell)

### Inferences
- Regime map: decode at batch ≤32 → weight-only W4A16 (Marlin/FLUTE) is optimal and KV quantization only matters if context is long enough that KV reads dominate weight reads; batch 32–256 → W4A8/W8A8 with INT8/FP8 TCs (QServe); prefill → W4A4/NVFP4 is justified (Mix-Quant). No paper gives a crossover formula in terms of (batch, context, model size, HBM bandwidth).
- Most "throughput" numbers in KV-quantization papers are *capacity-constrained* throughput (bigger batch under fixed memory), measured with in-flight batching off or at a fixed max batch — not latency improvements. Papers that measured latency honestly (FlatQuant, TurboQuant audit, KVarN) report ≤1x at small batch.
- NVFP4 KV + FP4 attention is the only path where storing and computing in 4-bit coincide; it exists only on Blackwell and only through ModelOpt/FlashMLA pipelines today.

### Gaps
- No public profile of per-token activation-quantization kernel time vs GEMM time.
- No neutral leaderboard comparing quantization to eviction at equal bytes and equal latency (KVPress has no quantization presses).
- No crossover model for when KV quantization pays off in latency rather than capacity.

## KQ9. Theory: KV distortion vs attention error, JL/unbiased estimators, per-channel vs per-token optimality, "rotation makes keys isotropic", effective temperature

### Takeaway
Existing theory is estimator-level: QJL gives an unbiased inner-product estimator from sign-quantized JL-projected keys; TurboQuant shows that after a random rotation each coordinate of a unit vector is marginally symmetric-Beta so a dimension-only Lloyd-Max codebook is near-MSE-optimal; RaBitQ-style binary codes give unbiased estimates with O(1/√d) error. None of these bounds the *attention output* or token-level error, OSCAR/Spend-Bits argue rotations equalize marginal variance but ignore the anisotropic query covariance that actually weights the error, softmax bounds are first-order (Jacobian) or crude (e^{±2η}), and no paper formalizes "effective temperature" or entropy-dependent error.

### Cited Findings
- QJL (V/S) [THEORY]: unbiased inner-product estimator when one side is sign-quantized after JL and the other is JL-projected unquantized; "provably minimal relative distortion on attention scores"; no quantization constants. Assumptions: random (Gaussian) projection; distortion controlled by projection dimension m (256/512 used). — [Source](https://github.com/amirzandieh/QJL); [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/34773)
- TurboQuant (S via OCTOPUS 2605.21226 and 0xSero audit) [THEORY]: random orthogonal rotation → coordinates of a unit vector marginally symmetric-Beta on [−1,1] → optimal scalar codebook depends only on (d, b); QJL 1-bit residual makes the combined inner-product estimator unbiased. Assumptions: norm stored/known; marginal (not joint) distribution; MSE objective. [CRIT] community found the QJL residual harmful and value quantization the bottleneck. — [OCTOPUS](https://www.alphaxiv.org/abs/2605.21226.md); [audit](https://github.com/0xSero/turboquant)
- OSCAR (arXiv 2605.17757) [THEORY] (S): logit error from channel-j noise is weighted by λ_j (query energy along j); real query covariance is "sharply anisotropic" — so isotropy of *keys* after rotation is not the relevant quantity; proposes offline spectral covariance-aware rotation for 2-bit KV. — [Source](https://arxiv.org/abs/2605.17757)
- "Spend Bits Where Queries Look" (arXiv 2608.04074) [THEORY] (S): Hadamard-type rotations equalize variance across entries rather than compacting energy; closed-form key transforms from calibration statistics under high-resolution quantization theory, targeting attention-product distortion rather than MSE. — [Source](https://www.alphaxiv.org/abs/2608.04074.md)
- KVLinC (S): empirically, raw keys channel-wise + Hadamard-rotated values token-wise is best — i.e., rotation helps values, not keys — contradicting the "rotate keys" default of QuaRot/RotateKV/TurboQuant. — [Source](https://arxiv.org/abs/2510.05373)
- Runtime-certified (2605.20868) [THEORY] (S): value error ≤ max per-token reconstruction error (convex combination, length-independent); key error → per-head/per-step attention-distribution bound; local, not end-to-end. — [Source](https://arxiv.org/abs/2605.20868)
- SpectrumKV (2606.08635) [THEORY] (S): |Δlogit| ≤ η ⇒ probability ratio in [e^{−2η}, e^{2η}]. — [Source](https://arxiv.org/abs/2606.08635)
- Jacobian noise injection (2608.20988) [THEORY] (S): first-order attention-weight perturbation via softmax Jacobian; bound degrades with ||J|| which is state-dependent. — [Source](https://arxiv.org/abs/2608.20988)
- "Faster Than Flash" (2609.00097) [THEORY] (S): score error ∝ ||q||·(projection of noise), √d scaling, tail bound in d. — [Source](https://arxiv.org/abs/2609.00097)
- RaBitQCache (2606.31519) (S) builds on RaBitQ (M: unbiased estimator with O(1/√D) error for rotated binary codes). — [Source](https://arxiv.org/abs/2606.31519)
- Rate-distortion allocation (S): RDKV (2605.08317) — joint eviction + quantization bit allocation; KV-COBRA (2609.24298) — bit/rank co-allocation; "Pricing the Risk of Runtime Compression" (2608.15810) — anytime-valid admission. — [RDKV](https://arxiv.org/abs/2605.08317)
- DFRot (2412.00648) (S): randomized Hadamard > orthogonal at W4A4, "reason unknown". — [Source](https://arxiv.org/abs/2412.00648)
- KIVI/KVQuant (V/S): per-channel keys / per-token values is justified empirically by outlier channels and streaming constraints, not by an optimality proof. — [KIVI](https://github.com/jy-yuan/KIVI)

### Inferences
- "Rotation makes keys isotropic" is true only marginally: a random rotation makes the *per-coordinate marginal* of a fixed vector symmetric-Beta, but it does not change the covariance structure relevant to q·k error, which is weighted by the query covariance (OSCAR). An MSE-optimal rotated scalar quantizer therefore spends bits uniformly over directions the queries never probe — a precise statement of why covariance-aware (KLT/PCA-like) transforms should beat Hadamard for *attention* error, consistent with Spend-Bits and OSCAR, and inconsistent with TurboQuant's near-optimality claim unless queries are isotropic.
- Unbiased logits do not give unbiased attention: for zero-mean logit noise ε_j, E[exp(s_j+ε_j)] = exp(s_j)·E[e^{ε_j}] ≥ exp(s_j) (Jensen); if the noise variance is the *same* for all keys the factor cancels in the softmax, but any per-token variance heterogeneity (different norms, per-token scale error — KVarN's diagnosis) biases attention toward noisier tokens. This is a candidate explanation for the "QJL hurts" observation and for why Gaussian logit noise acts like a *temperature increase* (flattening) — but no source states or proves it.
- Per-channel vs per-token: per-channel key scaling is a diagonal (channel) whitening; Hadamard is a dense orthogonal mixing; the right comparison is kurtosis-per-channel vs cross-channel correlation — a formal criterion for when each wins is absent.

### Gaps
- No bound linking KV-quantization distortion to attention *output* error as a function of attention entropy or sparsity.
- No theorem on bias of softmax under heteroscedastic quantization noise ("effective temperature").
- No proof of when per-channel scaling beats rotation for keys; KVLinC's empirical reversal (rotate values, not keys) is unexplained.
- TurboQuant/QJL theorem statements, constants and assumptions could not be read directly this session.

## KQ10. Cross-cutting gaps and contradictions between papers (for idea generation)

### Takeaway
The field's load-bearing claims disagree on at least eight points — QJL's value, int4-KV safety, which of K/V is harder, whether KV quantization speeds decode, eviction vs quantization, how to treat the MLA RoPE branch, MSE-optimal vs attention-optimal transforms, and the meaning of "lossless" in quantized speculative decoding — and most evidence is self-reported, perplexity-dominated, and evaluated in prefill-like settings.

### Cited Findings (contradictions, each with both sides)
1. **QJL residual helps vs hurts.** QJL/TurboQuant: unbiased estimator with minimal distortion (V/S). vLLM TurboQuant docs: "community consensus (5+ independent groups) found it hurts attention quality by amplifying variance through softmax", so vLLM omits it (S). — [QJL](https://github.com/amirzandieh/QJL); [vLLM](https://docs.vllm.ai/en/latest/api/vllm/model_executor/layers/quantization/turboquant/)
2. **"INT4 KV is free" vs int4 collapse.** Atom slides: 4-bit RTN KV maintains accuracy (S). Hurwitz (2605.27646), SpectrumKV (2606.08635), Apple-silicon (2605.05699): naive int4 collapses RULER / fails on Qwen2.5-7B and Qwen3-8B (S). — [Atom slides](https://mlsys.org/media/mlsys-2024/Slides/2655.pdf); [Hurwitz](https://arxiv.org/abs/2605.27646)
3. **Keys harder vs values harder.** KVTuner, MixKVQ, KVarN, KVLinC allocate more bits to keys (S/V). TurboQuant audit: at 3b/2b, key cos-sim 1.000 but value cos-sim 0.940 — values are the bottleneck (V). — [KVTuner](https://arxiv.org/abs/2502.04420); [audit](https://github.com/0xSero/turboquant)
4. **Rotate keys vs rotate values.** QuaRot/RotateKV/TurboQuant rotate keys; KVLinC finds raw per-channel keys + rotated per-token values best (S). — [KVLinC](https://arxiv.org/abs/2510.05373)
5. **Speedups.** KIVI 2.35–3.47x, QServe up to 3.47x, PatternKV 1.5x (self-reported, batch-enlarged) vs HF docs (latency harm at short context), PolarQuant (KIVI slower than exact), TurboQuant audit (+3% within noise), KVarN 0.94x on MLA, FlatQuant decode 0.71x at bs=1 (V). — [FlatQuant](https://github.com/ruikangliu/FlatQuant); [HF](https://raw.githubusercontent.com/huggingface/transformers/main/docs/source/en/kv_cache.md)
6. **Eviction vs quantization.** ZipCache, 2407.01527: quantization safer for retrieval. ReST-KV: eviction+4-bit at 6.25% beats 2-bit quantization. CAKE: complementary. 2607.05399: ratio not predictive. KVPress: no quantization in leaderboard (V). — [2407.01527](https://arxiv.org/abs/2407.01527); [ReST-KV](https://arxiv.org/abs/2605.08840); [KVPress](https://github.com/NVIDIA/kvpress)

### Inferences (open problems distilled)
- A softmax-aware (not MSE-aware) distortion theory for KV quantization that explains QJL's failure and predicts K-vs-V bit allocation as a function of query covariance and attention entropy.
- Model-dependence of int4-KV collapse (Qwen) — likely a bias/outlier-structure effect — unexplained and unmodeled.
- Decode-time error accumulation over thousands of steps has no theory and no standard benchmark; long-CoT reasoning is where 2-bit KV fails first.
- Latency-honest evaluation: KV quantization wins are capacity wins; fused dequant-in-attention kernels that beat FP16 at small batch exist only in a few systems (QServe, KVarN, Apple-silicon int4).
- MLA latent quantization under weight absorption, MoE activation/routing quantization, and acceptance-vs-draft-bit-width curves in speculative decoding are each covered by ≤1 paper.
- Security: batch-shared dynamic scales leak information (Quantamination) — per-token scaling is both faster and safer; static per-tensor FP8 KV scales (llm-compressor default) avoid the leak but vLLM's default scale of 1.0 is uncalibrated.
