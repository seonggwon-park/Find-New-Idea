# 2405.18137 — Exploiting LLM Quantization (Egashira, Vero, Staab, He, Vechev; NeurIPS 2024)

First-pass verdict (verify/batch_02.md, SUMMARY.md): confirmed, NeurIPS 2024, Table 6 numbers, "dither" 0 hits, scale-frozen nuance. This note adds the exact construction and what that first pass did not record.

## Q1. Exact construction of the "preimage box"
- Unified formalization (Sec 3): LLM.int8(), NF4, FP4 "first subdivide the model weights into blocks W of size K. Next, the weights are normalized to the interval [−1, 1] by dividing each weight by the scaling parameter s := max_{w∈W}|w|. Finally, each normalized weight w_i is rounded to the nearest symbol α_j in the quantization alphabet A ⊂ [−1, 1]... ŵ_i = s·α_j". "The only difference among the three considered quantization methods lies in their respective alphabet A. Details regarding the construction of A are not crucial for our attack and are thus omitted."
- Eq. (1), for w_i assigned to α_j (s = |w_K| w.l.o.g.):
  - j = 1: (s·α_1, s·(α_1+α_2)/2)
  - 1 < j < |A|: (s·(α_{j−1}+α_j)/2, s·(α_j+α_{j+1})/2)
  - j = |A|: (s·(α_{n−1}+α_n)/2, s·α_n)
  i.e. the nearest-neighbour (Voronoi) cell of α_j scaled by s, with the outer cells clipped at ±s (not extending to ±∞, because |w_i| ≤ s must hold for s to remain the max).
- "To ensure that the scale s is preserved, we constrain w_K to stay fixed throughout step 3." => the set is a product of intervals (a box) only *conditional on fixing the absmax element*; it is a sufficient, not necessary, set (an inner approximation of the true preimage). The paper itself says: "if the constraints are respected in the repair phase, the resulting model is guaranteed quantize to the same malicious model Q_m" — a guarantee, but no claim of exact characterization despite the abstract's "constraints that characterize all full-precision models that map to the same quantized model".
- Multi-method: "compute the interval constraints for each method and use the intersection as the final constraint." Main experiments use this all-at-once intersection.
- Method-specific (App. A.1):
  - LLM.int8(): "takes each row as one block"; interpreted as mapping w/s to {−1, −126/127, ..., 1}. Mixed-precision decomposition (outlier activation columns, default threshold 6.0) handled because "our method preserves the dequantization operation of the weights. Therefore, our method is independent of the outlier".
  - NF4/FP4: differ only in alphabet; NF4 double quantization (256 scales re-quantized) "applicable regardless of this choice because we fully preserve the scaling parameters of each block in the first stage".
  - Constraints computed by calling the real bitsandbytes quantization functions "to avoid rounding errors": "< 1 minute" for LLM.int8(), "approximately 30 minutes" for NF4/FP4 on 3B models (App. A.2).
- No theorem anywhere. "it is not guaranteed that the bound in step 2 is wide enough to find a benign model, but we demonstrate that this is empirically possible" (Sec 3.1).
- Ablation App. (Table 8): effectiveness "All-at-once < LLM.int8() < NF4 ≈ FP4" on StarCoder-1b; for Phi-2 "even the intersected intervals are sufficiently large".
- Sec 4.4 Constraint Width: Fig. 3 x-axis "Quantization Interval Width [1e-04]" (range ~0–20 ×1e-4); Phi-2 "almost 2× wider quantization intervals" than StarCoder-1b; contrast up to 80.1% vs 56.3%.
- Adjustments vs Ma et al. [14] (TDSC 2023, "Quantization backdoors to deep learning commercial frameworks"): removed the quantization-aware regularizer ("~30× overhead"), freeze non-quantized weights, use reference implementations.

## Q2. Noise defense (Sec 4.4 "Noise Defense", Table 6)
- Noise type: "Gaussian noise N(0, σ)" added to model weights before quantization (whether σ is std or variance is not stated; it is absolute, not relative to block scale s; single realization; no per-block scaling).
- Setting: Phi-2, vulnerable code generation, LLM.int8() only. One model, one scenario, one quantizer.
- Table 6 (code security FP32 / Int8; HumanEval FP32 / Int8; TruthfulQA FP32 / Int8):
  - σ=0: 98.0 / 18.5; 48.7 / 43.6; 40.6 / 36.9
  - σ=1e-4: 97.9 / 32.6; 48.8 / 47.0; 40.4 / 37.3
  - σ=1e-3: 98.4 / 97.5; 48.0 / 47.8; 40.4 / 39.7
  - σ=1e-2: 99.8 / 98.8; 9.8 / 13.8; 17.7 / 17.7 (utility collapse on both HumanEval and TruthfulQA)
- Quote: "At σ = 10−3 adding noise proves to be an effective defense against the attack, removing the security contrast while maintaining utility." Text says utility "remains unaffected on MMLU and TruthfulQA" but MMLU is not in Table 6.
- Caveat quote: "potential consequences beyond benchmark performance of the noise addition remain unclear and have to be thoroughly investigated before noise-based defenses can be adopted in quantization schemes. We leave the study of this problem as a future work item outside the scope of this paper."
- Scale observation (my inference, not the paper's): σ=1e-3 is comparable to or larger than the int8 interval widths plotted in Fig. 3 (order 1e-4 to 2e-3), i.e. the working defense moves weights by about one quantization cell, which is why it re-randomizes the cell assignment. σ=1e-4 (below cell width) only partly helps (32.6). No analysis of this ratio in the paper.

## Q3. Dither / stochastic rounding / randomized quantization
- "dither": 0 hits. "stochastic": only in the Adam reference title. "random": no relevant hit. No randomized-rounding or secret-seed defense is discussed.
- However the Gaussian pre-quantization weight perturbation *is* a non-subtractive Gaussian dither applied once by the defender (the noise stays in the dequantized weights). The paper does not frame it this way, gives no theory, and does not consider subtractive/uniform dither, stochastic rounding, or per-user random seeds.

## Own limitations / future work (Sec 5)
- "our investigation did not extend to (i) optimization-based quantization and recent methods that quantize activation caching [46 GEAR, 47 KIVI] ... and (ii) larger LLMs, such as those with 70 billion parameters".
- Defense: "the quantization attack can be mitigated to a large extent if the quantized model versions can be thoroughly tested"; noise defense "is a promising direction, rigorous investigations are necessary to find its effect beyond benchmark performance".
- Mitigation: "training with stronger regularization to keep the weight magnitude small can make the model more robust"; "adjusted quantization methods should be developed to protect against quantization attacks".

## Implications for the report
1. Line 287 "dither를 방어로 검토한 문헌은 검색에서 나오지 않았다" is literally true but misleading: Egashira's Table 6 defense is a (non-subtractive, Gaussian, absolute-σ, one-shot) dither of the weights. Rephrase: "Gaussian 가중치 노이즈(사실상 비감산 dither, σ=1e-3 절대값, Phi-2/LLM.int8() 1개 설정)는 실험적으로만 검토됐고, 감산 dither·확률적 반올림·비밀 seed 무작위 양자화와 그 보장(예: preimage box 폭 대비 σ의 조건)은 검토되지 않았다." The novelty of a dither idea must be the theory (σ relative to cell width Δ=s·(α_{j+1}−α_j)/2, guarantee against interval-constrained PGD) and the subtractive/keyed variants, not "noise as defense".
2. "preimage box" (line 45, 287): add that the box is Eq. (1) Voronoi cells of the alphabet scaled by s, outer cells clipped at ±s, valid only with the block's absmax element frozen, hence an inner (sufficient) set; the abstract's "characterize all full-precision models" overstates it. For the report's unified-theorem idea, the exact preimage is a union of boxes over which element attains the max (and over sign of s), not a single box.
3. "NF4/INT8/FP4": write "LLM.int8()/NF4/FP4 (bitsandbytes zero-shot, absmax-blockwise)"; attack targets the intersection of all three by default.
4. The defense evidence should be reported with its scope: one model, one scenario, one quantizer; σ=1e-2 destroys utility (HumanEval 9.8/13.8, TruthfulQA 17.7/17.7), so the usable window is about one decade wide.
