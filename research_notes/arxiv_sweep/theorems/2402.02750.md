## 0. Bottom line for the report

- **There is no theorem, lemma, proposition, corollary, proof or bound anywhere in the paper.** A grep for `theorem|lemma|proposition|corollary|proof|assum` over the full text returns zero hits. The word "softmax" appears exactly three times: in Eq. (1) (attention definition), in the Table 2 definition of the attention-score error, and in Algorithm 1 (Appendix A). There is no analytic statement about how quantization error propagates through softmax.
- KIVI's justification for "key per-channel / value per-token" is **three-layered and all empirical**: (i) an accuracy ablation over the four configurations (Table 1, Section 3.1, OB1–OB3); (ii) a magnitude visualization showing fixed outlier channels in K and none in V (Figure 2, Section 3.2); (iii) measured Frobenius relative errors of the reconstructed cache, of the attention matrix A, and of the attention output A·X_V (Table 2, Section 3.2), plus a one-paragraph "intuition" via attention sparsity and Eq. (2).
- Crucially, the paper itself says the outlier story **does not** explain the value side: "Figure 2 alone cannot explain OB2". The value-side argument is attention sparsity + per-token error confinement, not outliers and not streaming.
- Streaming is **not** a justification for the asymmetry in KIVI. It is (a) the reason prior work (FlexGen) used per-token for both, and (b) an implementation obstacle for per-channel K that KIVI works around with the grouped/residual split (Section 3.3).

## 1. Setup and notation (Section 2, Eq. 1)

> "Prefill Phase. Let X ∈ R^{b×l_prompt×d} be the input tensor, where b is the batch size, l_prompt is the length of the input prompt, and d is the model hidden size. ... X_K = X W_K, X_V = X W_V"
> "Decoding Phase. ... X_K ← Concat(X_K, t_K), X_V ← Concat(X_V, t_V), then calculate the attention output as: t_Q = t W_Q, A = Softmax(t_Q X_Kᵀ), t_O = A X_V, (1)"

Quantizer (Section 3.1), asymmetric round-to-nearest with min/max range:
> "The B-bit integer quantization-dequantization process can be expressed as: Q(X) = ⌊(X − z_X)/s_X⌉, X′ = Q(X)·s_X + z_X, where z_X = min X is the zero-point, s_X = (max X − min X)/(2^B − 1) is the scaling factor, and ⌊·⌉ is the rounding operation."

Definition of the two directions (Figure 1 caption): "X ∈ R^{l_prompt×d} is key/value cache where l_prompt is the number of tokens and d is the number of channels. z_X is the zero-point, s_X is the scaling factor." Per-token groups along d within one token row; per-channel groups along tokens within one channel column. Group size G = 32 in all preliminary experiments.

Why RTN at all (Section 3.1): "KV cache functions as a streaming data structure, where the new tensor arrives sequentially. Thus, optimization-based methods like GPTQ (Frantar et al., 2022) are unsuitable for quantizing KV cache due to the overhead."

Why prior work used per-token for both (Section 2, last paragraph): "Considering the streaming nature of KV cache, previous studies often apply per-token quantization to both key and value cache since the newly quantized KV cache can be naively added to the existing quantized one along the token dimension (Sheng et al., 2023). While per-channel quantization is non-trivial, we have designed a padding method to implement per-channel quantization to explore its effect on both key and value cache."

## 2. Justification layer 1 — the configuration ablation (Section 3.1, Table 1)

Table 1 (fake/simulated group-wise quantization, Llama-2-13B, G = 32, zero-padding for per-channel so all tokens are quantized; C = per-channel, T = per-token):

| Config | CoQA | TruthfulQA |
|---|---|---|
| 16bit | 66.37 | 29.53 |
| 4bit (K-T, V-T) | 66.48 | 29.51 |
| 2bit (K-T, V-T) | 52.93 | 24.98 |
| 2bit (K-C, V-C) | 2.88 | 0.74 |
| 2bit (K-T, V-C) | 2.80 | 0.26 |
| 2bit (K-C, V-T) | 63.53 | 28.60 |

The three observations, verbatim:
> "OB 1. When using the commonly used per-token quantization to both key and value caches, INT4 precision can maintain accuracy. However, reducing it to INT2 results in a notable accuracy drop."
> "OB 2. When value cache is quantized per-channel, the accuracy significantly worsens regardless of how key cache is quantized."
> "OB 3. When using a lower numerical precision such as INT2, the most accurate approach is to quantize key cache per-channel and value cache per-token."

Table 3 (Section 4.2.1) repeats the four fake-2bit configurations on Llama-2-7B/13B, Llama-2-7B/13B-Chat, Falcon-7B, Mistral-7B over CoQA/TruthfulQA/GSM8K: "We observe that '2bit (K per-channel, V per-token)' consistently achieves the best results compared to all other configurations." But: "for hard generation tasks such as GSM8K, the fake '2bit (K per-channel, V per-token)' quantization results are significantly worse than the full precision counterparts. However, for KIVI in Table 3, we observe that the accuracy drop is only around 2% for GSM8K across different models." The difference is the full-precision residual window of the most recent R tokens, which "is crucial to maintaining accuracy for hard generation tasks such as mathematical reasoning."

## 3. Justification layer 2 — outlier channels in K, none in V (Section 3.2, Figure 2)

Figure 2 caption: "Magnitude of key and value cache for Llama-2-13B and Falcon-7B. We observe (1) for key cache, there are a few channels whose magnitudes are very large. (2) for value cache, there is no obvious outlier pattern." (Panels shown include "Llama-2-13B Layer 16 Head 0 Key Cache".)

Key-side argument, verbatim (Section 3.2, "Analysis of Key Cache"):
> "The above observation for key cache aligns with previous findings that certain fixed columns in activations exhibit larger outliers (Dettmers et al., 2022; Lin et al., 2023). The persistence of outliers within each channel means that per-channel quantization can confine the quantization error to each individual channel without impacting the other normal channels. Thus, Figure 2 explains why key cache should be quantized per-channel."

Same claim in the Introduction bullets: "For key cache, there are a few fixed channels whose magnitudes are very large, which is consistent with previous finding (Lin et al., 2023; Xiao et al., 2023a). Thus, as shown in Figure 1 right, key cache should be quantized per-channel ... In this way, it can confine the error to each individual channel, without impacting the other normal channels."

Value side — the paper explicitly says the outlier picture is insufficient (Section 3.2, "Analysis of Value Cache"):
> "Unlike key cache, value cache does not show the channel-wise outlier pattern. Furthermore, Figure 2 alone cannot explain OB2, which indicates value cache should only be quantized per-token. This is because Figure 2 implies that errors should be comparable for both per-token and per-channel quantization, given the absence of a clear pattern."

Introduction bullet on V: "Although value cache has no obvious outlier pattern, we experimentally show that it can only be quantized per-token because it is used to calculate the attention output, which is essentially a value cache mixer. As shown in Figure 1 left, the per-token quantization can confine the error inside each individual token and ensure that the quantization of one token does not adversely impact the others."

## 4. Justification layer 3 — measured relative errors (Section 3.2, Table 2)

Table 2, "The relative error statistics averaged over all layers and all heads", Llama-2-13B (cell layout from the arXiv HTML; the PDF text extraction scrambles the order). The paper does not state the unit; values are reported as printed. Quantities: key reconstruction error ‖X_K − X′_K‖_F/‖X_K‖_F; attention-score error ‖A − A′‖_F/‖A‖_F with A = Softmax(t_Q X_Kᵀ); value reconstruction error ‖X_V − X′_V‖_F/‖X_V‖_F; output error ∆ = ‖A X_V − A X′_V‖_F/‖A X_V‖_F.

| Llama-2-13B | K Per-Token | K Per-Channel |
|---|---|---|
| Avg. ‖X_K − X′_K‖_F/‖X_K‖_F | 13.67 | 4.55 |
| Avg. ‖A − A′‖_F/‖A‖_F | 47.00 | 9.60 |
| Attention sparsity | 84.3% | |
| | **V Per-Token** | **V Per-Channel** |
| Avg. ‖X_V − X′_V‖_F/‖X_V‖_F | 4.57 | 3.73 |
| Avg. ∆ | 3.55 | 49.89 |

Prose on K: "In Table 2 we show key cache relative reconstruction error ‖X_K − X′_K‖_F/‖X_K‖_F, along with the relative attention score error ‖A − A′‖_F/‖A‖_F where A = Softmax(t_Q X_Kᵀ). We observe that the per-token quantization can lead to almost 5× larger attention score error than per-channel quantization, which is consistent with Figure 2." (47.00 / 9.60 = 4.9.)

Prose on V: "As shown in Equation (1), value cache is used to calculate the attention output t_O. Instead of analyzing the quantization error of value cache X_V, in Table 2 we analyze the relative error ∆ = ‖A X_V − A X′_V‖_F/‖A X_V‖_F with different quantization configurations. Surprisingly, we observe that the per-token quantization error is almost 15× smaller than per-channel quantization, which explains why OB2 happens." (49.89 / 3.55 = 14.1.)

Two facts in this table that the report should not gloss over:
1. For V, **per-channel has the lower element-wise reconstruction error** (3.73 vs 4.57) yet a 14× larger output error. So the direction choice for V is not about reconstruction MSE at all; it is about how the error enters A·X_V.
2. For K, per-channel wins on both reconstruction (3×) and attention error (4.9×); the paper does not decompose the attention error into the softmax step, it only reports the end-to-end Frobenius number. "Attention sparsity 84.3%" is given in the table without a definition in the text.

## 5. The only "mechanism" statement — attention sparsity and Eq. (2) (Section 3.2)

This is the closest thing to theory in the paper; it is labelled by the authors as an intuition, carries no assumptions, no bound and no proof:
> "The intuition behind this observation stems from the attention sparsity. Equation (1) can be written as:
>   [A X_V]_{i∗} = Σ_{j=1}^{l_prompt} A_{ij} [X_V]_{j∗},   (2)
> where [X_V]_{j∗} is the j-th row of X_V. From Equation (2), the attention output is the weighted summation of value cache across various tokens, with the weights being the attention scores. Since the attention score is highly sparse (Tian et al., 2023), the output is just the combination of value caches of a few important tokens. The per-token quantization can confine the error to each individual token. Thus, quantizing other tokens does not affect the accuracy of important tokens. Consequently, per-token quantization leads to a much smaller relative error ∆."

Reading: the argument is that with per-token scales, each row's error is set by that row's own range, so rows that get large attention weight are not polluted by the range of other rows in the group; with per-channel scales over a group of 32 tokens, an important token's row inherits the range of its 31 neighbours in every channel. No analogous argument is given for why K should be per-channel beyond "confine the error to each channel" — in particular there is no statement about the softmax, about logit noise variance, about heteroscedasticity across tokens, or about attention-sink/outlier-token mass.

## 6. Algorithm and the role of streaming (Section 3.3, Appendix A, Algorithm 1)

> "As we previously analyzed, key cache should be quantized per-channel and value cache should be quantized per-token. Recall that key and value cache of newly generated tokens arrive sequentially. From the implementation perspective, per-token quantization aligns well with streaming settings, allowing newly quantized tensors to be directly appended to the existing quantized value cache by token dimension. However, for per-channel quantization, the quantization process spans across different tokens, which cannot be directly implemented in the streaming setting. As shown in Figure 3, our key idea to solve this problem is to group key cache every G tokens and quantize them separately."

Mechanics: X_K split into grouped X_Kg = X_K[: l − r] (quantized per-channel in G-token groups) and residual X_Kr (full precision, ≤ R tokens, R divisible by G); when X_Kr reaches R tokens it is quantized and appended. Values: a queue of the most recent R tokens is kept full precision, older ones are quantized per-token. Eq. (3): A_g = t_Q Q(X_Kg)ᵀ, A_r = t_Q X_Krᵀ, A = Concat([A_g, A_r]); Algorithm 1 then applies Softmax over the concatenation and computes t_O = A_g Q(X_Vg) + A_r X_Vr. "During the prefill phase, the exact key and value tensors are passed to the next layers, although only the quantized KV cache is retained in memory." Dequantization is fused into matmul ("Q_MatMul", CUDA) and the quantization kernel is in Triton; "fully compatible with weight-only quantization".

Hyperparameters (Section 4.2.3, Table 5, Llama-2-13B GSM8K, KIVI-2): group size 32 / 64 / 128 → 20.77 / 21.00 / 17.29 ("group sizes 32 and 64 yield similar results, whereas the performance significantly decreases when the group size reaches 128"); residual length 32 / 64 / 96 / 128 → 20.62 / 19.86 / 20.55 / 20.77. Appendix C: R = 32 "does not result in a substantial performance gap" and gives higher compression.

## 7. Headline empirical claims (abstract, Section 4)

- "KIVI can enable Llama, Falcon, and Mistral models to maintain almost the same quality while using 2.6× less peak memory (including model weight). This reduction in memory usage enables up to 4× larger batch size, bringing 2.35× ∼ 3.47× throughput on real LLM inference workload." (Abstract; Figure 5; workload synthesized from ShareGPT following vLLM, l_prompt = 161, l_gen = 338 on average.)
- LongBench (Table 4, 8–10), Needle-in-a-Haystack (Figure 4, Llama-3-8B-Instruct, Mistral-7B-Instruct-v0.2) are reported for KIVI-2/KIVI-4 vs 16-bit.

## 8. Limitations / future work — the paper's own words

There is no section titled "Limitations". The only explicit forward-looking statements are about kernel overhead:
- Section 4.2.4: "We also note that this speed-up can be greatly increased if we further fuse the KV cache quantization process with previous operations. We leave it as one of future work."
- Section 6 ("Conclusion and Future Work"): "In the future, we will further optimize the implementation to reduce the overhead of quantization process during the prefill and decoding phase."

Weaknesses the paper admits in passing (not framed as limitations):
- Pure asymmetric 2-bit without the full-precision residual window is "significantly worse than the full precision counterparts" on GSM8K (Section 4.2.1); the sliding window "is crucial" for math reasoning.
- Group size 128 degrades GSM8K noticeably (Table 5).
- Related work (Section 5): "One essential recipe of KIVI is the per-channel quantization scheme designed based on the observation made in Section 3.2 and Figure 2. ATOM (Zhao et al., 2024) also indicates that key cache exhibits more outliers compared to the value cache. ... A similar observation and approach has been independently discovered and developed in the concurrent work KVQuant (Hooper et al., 2024)." Token-eviction methods (H2O, Scissorhands, StreamingLLM) and system-level work (vLLM, S3) are called "orthogonal".

Not discussed at all: RoPE (pre- vs post-RoPE key quantization), attention sinks / massive-activation tokens, any bias (as opposed to error magnitude) in the attention distribution, calibration/entropy of attention, GQA/MLA, and any theoretical optimality of the chosen directions.

## 9. What the report (`reports/LLM 양자화 연구 아이디어 10선.md`) must change

Current sentence (line 53): "KIVI의 per-channel K / per-token V는 'outlier 채널'과 '스트리밍 편의'로 정당화됐고 최적성 증명이 없다."

1. "최적성 증명이 없다" is **verified** — strengthen it: the paper contains no theorem, lemma or bound of any kind, and no statement about softmax beyond its definition in Eq. (1).
2. "'스트리밍 편의'로 정당화됐고" is **wrong in attribution**. In KIVI, streaming is why *prior* work (FlexGen) used per-token for both, and an *obstacle* that KIVI's grouped/residual design (Section 3.3) exists to overcome. It is never offered as a reason for the K/V asymmetry. Replace with the actual three-part justification: Table 1 ablation (OB1–OB3), Figure 2 outlier channels (K only), Table 2 measured errors.
3. The value-side justification is **not outliers**. KIVI says "Figure 2 alone cannot explain OB2" and gives the attention-sparsity / Eq. (2) error-confinement intuition plus the measured ∆ (3.55 vs 49.89). Idea 1's claim "value는 softmax를 거치지 않고 선형으로 들어가므로 per-token이 무해하다" (line 73) is compatible with KIVI's Eq. (2) but is not what KIVI argues; KIVI's point is that per-channel V spreads the error of unimportant tokens into the few heavily-attended tokens' rows. Also note KIVI's Table 2 shows per-channel V has *lower* element MSE (3.73 vs 4.57) — so any "MSE-optimal direction" framing for V is contradicted by KIVI's own numbers; the gap is entirely in how the error propagates through A·X_V.
4. The key-side evidence in KIVI is a 4.9× end-to-end Frobenius attention error (47.00 vs 9.60) and a 3× reconstruction error (13.67 vs 4.55). The report's Idea 1 story (per-token K ⇒ heteroscedastic logit noise ⇒ systematic bias toward large-range/sink tokens) is **not tested or mentioned** in KIVI; KIVI measures error magnitude only, never bias, never sink mass. The gap statement should say exactly this: KIVI measures ‖A − A′‖_F but never decomposes it into a bias term, so the "2차 편향" claim is genuinely open rather than "explained by outliers".
5. Cite the specific anchors: Section 3.1 OB1–OB3 + Table 1; Section 3.2 Figure 2 + Table 2 + Eq. (2); Section 3.3 for the streaming workaround; ICML 2024 as venue; v2 (2024-07-25) as the current version.
