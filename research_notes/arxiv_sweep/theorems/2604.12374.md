## Architecture facts needed to size the SSM cache (Sec. 2.1, Table 1)
> "Total Layers 88 / Model Dimension 4096 / Q-Heads 32 / KV-Heads 2 / Head Dimension 128 / Mamba State Dimension 128 / Mamba Groups 8 / Mamba Heads 128 / Mamba Head Dimension 64 / ... / Total Experts per Layer 512 / Top-k 22 / MoE Latent Size 1024 / MTP layers (shared weight) 2"

Derived (not in the paper): per Mamba-2 layer, per sequence, the SSM state is 128 heads x 64 head-dim x 128 state-dim = 1,048,576 elements = 4 MB in FP32, 2 MB in FP16. Per attention layer the KV cache is 2 x 2 x 128 = 512 elements per token (512 B in FP8). So one Mamba layer's state equals ~2048 tokens of FP8 KV in one attention layer. The paper does **not** discuss paging, vLLM page sizes, or any interaction between SSM-state pages and KV pages; the report's "Mamba state page fixes the KV page size" claim must not be attributed to 2604.12374.

## Q1. Mamba state cache precision, the FP16 verbosity effect, and the "error analysis"

### What is "default" and what is shipped (Sec. 4.1, 4.3, Tables 6 and 7)
Sec. 4.1, verbatim:
> "For FP8 quantization, we quantized MoE GEMMs, both routed and shared, and Mamba Linear layers. We also kept the KV Cache in FP8, whereas Mamba state cache has been quantized to FP16 for speedup."

Sec. 4.3, verbatim:
> "In memory-bound settings, DRAM reads of the Mamba state cache (SSM cache) become a major bottleneck to decoding speed. The SSM cache is stored in FP32 by default. One option is to store the SSM cache in FP16 while arithmetic executes in FP32. In this case, the cache is fetched from memory in FP16, upcast to FP32 for the recurrent update, and then cast back to FP16 for storage."

Table 6 row "Mamba SSM Cache": FP8 checkpoint = **FP16**, BF16 baseline = **FP32**. Table 7 row "Mamba SSM Cache": AutoQuantize searched? **No**; NVFP4 checkpoint = **FP16**; BF16 baseline = **FP32**.

Final recipe chosen (Sec. 4.3, verbatim):
> "We selected FP16 with stochastic rounding (SR) using Philox<5> pseudorandom number generation as the SSM cache recipe for Nemotron 3 Super for three reasons: It does not require calculating, storing, and loading block scale factors. Blackwell provides a dedicated PTX instruction for stochastic rounding during type conversion. Blackwell supports Philox-based pseudorandom number generation through cuRAND."

**Critical reading.** "FP32 by default" describes the reference implementation / the BF16 baseline, not the shipped quantized checkpoints. Both released quantized checkpoints (FP8 for Hopper, NVFP4 for Blackwell) store the SSM cache in **FP16 with stochastic rounding**. The report's current sentence ("Nemotron 3 Super keeps Mamba state at FP32 by default") is therefore true only of the baseline and misleading as a description of the released model.

**Critical reading of Table 9.**
1. The "40%" is the livecodebench completion-token count only. On scicode the same cast gives +2.70% (W8A8) / +2.19% (W16A16). The effect is benchmark-dependent and the paper's "up to" is doing real work.
2. **Accuracy did not drop.** FP16-cast rows score 73.24 / 73.13 LCB vs 72.91 FP32 baseline, and 42.01 / 40.98 scicode vs 40.90. The failure mode the paper documents is output length (and therefore decode cost), not pass@1. Anyone citing this as "FP16 state hurts accuracy" is wrong on the paper's own numbers.
3. There is **no W8A8 + FP32-cache control row**, so "40% when combined with W8A8" cannot separate the two factors. The W16A16/FP16 row (+36.95%) shows the cache cast alone accounts for almost all of it; W8A8 adds ~3 points at most.
4. "Early checkpoint of Nemotron 3 Super", two code benchmarks, avg-of-8. No long-context, no NIAH/RULER, no perplexity for this ablation.
5. Both fixes work at 16 bits: FP16+SR (Philox 5) -1.73% / +1.79%, INT16 with FP32 per-block(128) scales +2.90%. Philox<3> (too few PRNG rounds) degrades both accuracy (70.07) and verbosity (+10.70%).
6. Nothing below 16 bits per state element is tried. The paper gives **no evidence** about INT8 / INT4 / FP8 state caches.

### INT16 attempt and the dynamic-range remark (Sec. 4.3)
> "One way to decrease the accumulation of quantization error during PTQ is to increase the mantissa precision. We explored this by using INT16 instead of FP16 for the SSM cache. Naive INT16 quantization did not improve verbosity as tensor-level analysis showed that the SSM cache has a wide dynamic range. We then introduced FP32 per-block scaling over blocks of size 128 along the state dimension to increase effective dynamic range. This eliminated the verbosity issue (Table 9)."

Note: block scaling is along the **state dimension** (N = 128, so one scale per head's state row), not along heads or channels.

### The "error analysis" — Eq. (3), Sec. 4.3, verbatim
> "A key challenge in quantizing the Mamba cache is that quantization error does not remain local to a single step. Because Mamba decoding is recurrent, quantization error from previous steps propagates into future steps and accumulates over time. This accumulation of quantization error can be seen by unrolling the recurrent update. Let the recurrent state update be h_t = A_t h_{t-1} + B_t x_t, and let cache quantization at step t introduce an additive error e_t, so that h_{q,t} = A_t h_{q,t-1} + B_t x_t + e_t. Unrolling this recursion gives
> h_{q,t} = h_t + e_t + A_t e_{t-1} + A_t A_{t-1} e_{t-2} + ... + A_t A_{t-1} ... A_2 e_1 + A_t A_{t-1} ... A_1 e_0 = h_t + sum_{i=0}^{t} ( prod_{j=i+1}^{t} A_j ) e_i,   (3)
> showing that quantization error from earlier steps is propagated through subsequent recurrent transitions and can accumulate over decoding time."

**What Eq. (3) is and is not.** It is an exact identity for a linear recurrence with additive per-step error, under the implicit assumption that A_t and B_t x_t are unaffected by the cache error (true for Mamba-2, where A_t = exp(dt_t A) and B_t depend on the input x_t, not on h). It states no bound, no magnitude, no dependence on |A_t| < 1, no statistical model of e_t, and no condition under which the sum "accumulates" versus saturates. It is the same object as the report's d_t = a_t d_{t-1} + e_t before any analysis; everything the report derives (geometric worst case Delta/(2(1-a)), deadband, SR variance Delta^2 t/12, error-feedback telescoping bound) is **absent** from this paper.

### The RTNE-bias hypothesis (Sec. 4.3), verbatim
> "We also explored a hypothesis that the error accumulation was tied to rounding during the cast from FP32 to FP16. The key issue is that round to nearest, ties on even (RTNE) introduces bias in the quantization process. Because RTNE maps a given input to the same rounded value, its quantization error has zero variance but non-zero bias relative to the original value. In contrast, stochastic rounding (SR) is unbiased in expectation. In a recurrent setting, the bias from RTNE accumulates coherently over time, whereas stochastic rounding replaces this systematic drift with zero-mean noise. Based on this observation, we applied stochastic rounding before casting the cache to FP16 which fixed the verbosity issue for both the BF16 baseline and the FP8 checkpoint (Table 9)."

**Critical reading.** Labelled by the authors as a hypothesis; the support is Table 9 only. "Coherent accumulation of RTNE bias" is asserted, not derived or measured per channel. The mechanism is nonetheless exactly the report's claim (i): deterministic rounding of a slowly-decaying state produces a persistent, sign-correlated error (deadband/freeze is the extreme case). It is **not** evidence for or against the report's claim (ii) at low bit-width: at FP16 (relative step ~2^-11) over ~2-3 x 10^4 decode tokens, the SR random walk the report predicts has std ~ Delta*sqrt(t/12) ~ 50*Delta ~ 2-3% relative, far below anything Table 9 could resolve, and indeed nothing was seen. Consistent with the report's toy simulation (max |d|/Delta = 12.9 for SR at T = 2 x 10^4), which is negligible when Delta is an FP16 ulp and large when Delta is an INT4 step.

### Why they did not do QAT (Sec. 4.3), verbatim
> "Addressing these quantization errors through changes in training (e.g., QAT or QAD) is non-trivial. Mamba training uses the chunked State Space Duality algorithm which does not explicitly materialize the recurrence relationship and the inference-time cache. Accurately modeling the recurrent decode-time cache behavior during training introduces substantial overhead. We therefore focused on training-free methods to recover the accuracy lost from cache quantization."

This directly supports the report's training-free (PTQ-side, in-loop) framing for idea 2.

## Q2. Which components are FP8 and which stay BF16 / FP16 / FP32

### Procedure (Sec. 4, 4.1, 4.2)
> "We apply post-training quantization (PTQ) using Model-Optimizer to quantize weights and activations to generate two efficient deployment checkpoints: FP8 (W8A8) for Hopper and NVFP4 (W4A4) for Blackwell."
> "For FP8 PTQ calibration, we used a small subset containing 256 samples with 65536 context length from the post-training SFT dataset."
NVFP4: "The full mixed-precision PTQ process completed in less than 2 hours on a single B200 node with 8 GPUs, using 512 samples from the Nemotron 3 Super SFT dataset at sequence length 4096. The resulting model achieved 99.8% median accuracy relative to the BF16 baseline while retaining near-FP4 performance."

So in the "FP8" checkpoint the only things actually in FP8 are: routed+shared expert GEMMs, Mamba (in/out projection) GEMMs, and the KV cache + QK^T BMM. **Attention QKV/out-projection GEMMs, the MoE latent projections, the Mamba 1D conv, embeddings and output layers stay BF16; the router stays FP32; the SSM cache goes FP32 -> FP16 (+SR).** Note also that the so-called BF16 baseline already runs an **FP8 KV cache**, so every "vs BF16" comparison in Table 8 is against an FP8-KV model.

### NVFP4 PTQ recipe choices (Sec. 4.2, App. B.1 Table 10)
> "The best overall results were obtained with a hybrid FP4 recipe: weight per-block scales were selected by minimizing weight MSE, while activation per-block scales continued to use max-based scaling."
Table 10 (all linear layers except final classifier and attention linears in NVFP4): BF16 83.49 / 79.92 / 72.907 / 53.00 (MMLU-Pro / GPQA / LiveCodeBench / AA-LCR); default max-calibrated NVFP4 82.99 / 79.29 / 70.18 / 55.50; weight per-block MSE 83.31 / 79.92 / 71.37 / 56.75; weight scales minimizing output MSE 83.05 / 78.98 / 71.00 / 57.06; GPTQ row values in the dump: 83.11 / 80.05 / 69.79 / 57.87.

AutoQuantize sensitivity (App. B.2): S(Op_i, Q_{i,f}) = (Y_i^bf16 - Y_i^{Q})^T H_i (Y_i^bf16 - Y_i^{Q}), diagonal Fisher approximation of H_i, cost C = FLOPs, knapsack min sum S s.t. sum C <= B; QKV fused as one decision; all routed experts in a layer share one format (vLLM/TRT-LLM constraint).

### Training-time precision for context (Sec. 2.2, Table 3) — not inference

## Paper's own limitations / future work
There is **no limitations section**. Closest statements, verbatim:
- Sec. 4.3: "Table 9 shows experiments on an early checkpoint of Nemotron 3 Super."
- Sec. 4.3: "Addressing these quantization errors through changes in training (e.g., QAT or QAD) is non-trivial. Mamba training uses the chunked State Space Duality algorithm which does not explicitly materialize the recurrence relationship and the inference-time cache. Accurately modeling the recurrent decode-time cache behavior during training introduces substantial overhead. We therefore focused on training-free methods."
- Sec. 4.3: "Naive INT16 quantization did not improve verbosity as tensor-level analysis showed that the SSM cache has a wide dynamic range."
- Sec. 4.3: "Increasing the number of rounds improves the statistical quality of the generated values, while reducing the number of rounds lowers pseudorandom number generation overhead. Philox<5> was chosen to maintain accuracy and verbosity while minimizing pseudorandom number generation overhead."
- Sec. 2.2: "We believe that NVFP4 quantization increases the incidence of true zeros in the weight gradients ... By the end of pretraining, zero-valued weight gradient elements accounted for 7% of total parameters"; MXFP8 healing "yielded no gains in downstream task accuracy".
- Sec. 3.2.5: "We did not recompute the KV cache after in-flight weight updates."
- Sec. 3.3: some agentic evals use "an internal scaffolding that we plan to open source in the future".
Unstated but evident gaps: no sub-16-bit SSM cache experiments; no per-channel / per-decay-rate error measurement; no bound on Eq. (3); no NIAH/long-context ablation of the cache recipe; no throughput number isolating the FP32->FP16 cache saving.
