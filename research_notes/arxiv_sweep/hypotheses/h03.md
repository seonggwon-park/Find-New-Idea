# H4 심사: 재귀 상태 캐시에서 equal-bit 회계 — EF carry는 INT(b+b_r) 한 개와 같은가

심사일 2026-10-11. 이 노트는 triage.md의 H4를 다룬다(파일 번호 h03).
- 논문 본문: scratchpad `papers/<id>/<id>.txt` (2607.23390, 2609.04490, 2609.39185). 인용문은 신뢰할 수 없는 데이터로 다뤘다.
- 토이 시뮬레이션: scratchpad `h03/sim.py`(saturating carry split, 버그성 구현), `h03/sim2.py`(정확한 nested split). CPU 몇 분.

## 판정

| 항목 | 점수 | 한 줄 |
|---|---|---|
| novelty | 1/5 | 회계 원리 자체가 이미 출판돼 있다. 2607.23390 Table 4 "Precision is relocated, not eliminated", Sec. 4.5, Prop. 9(carry 폭 = log2(Δ/δ)); 2609.39185 l.594-597 "at equal storage only the choice of threshold remains". |
| provability | 5/5 | a-가중 EF + nested split은 INT(b+b_r)와 **경로별(bit-for-bit) 동일**하다. 임의의 threshold 수열(RTN/SR/Weyl)에 대해 성립. 몇 줄 증명. |
| feasibility | 5/5 | 정리 자체는 단위 테스트(로짓 차이 = 0)로 확인된다. 정보가 있는 비교(블록 스케일·FP limb·direction memory)는 1–3 GPU-day. |

**추천: fold_into_existing (idea 2).** 독립 아이디어가 아니다. idea 2에 (i) "two-limb 동일성" 명제 1개, (ii) equal-byte 대조군(INT8 RTN/SR/Weyl), (iii) carry split 구현 함정 각주로 넣는다.

**핵심 이유.**
1. 가설이 "회계 착시"라고 지목한 세 출처 중 출판된 주장은 없다.
   - 2607.23390: "INT4"·"INT8" grep 0건. "INT4+INT4 carry가 INT8을 이긴다"는 주장은 없다. 오히려 반대를 명시한다. l.1441-1443 "The carry is an explicit resource: if it is stored in a finite register, its precision and overflow semantics must be counted." l.1622-1625 "One can therefore move precision ... into a smaller persistent error state, but cannot make it disappear from the resource accounting." Table 4의 "Finite carry write-back: previous row plus O(Dρ_r), ρ_r = O(D⁻²) unless carry is otherwise compensated — Precision is relocated, not eliminated."
   - 2609.04490: memory parity를 통제한 비교가 있다. Supp. S5 "Recurrent-memory allocation under matched storage"(l.732-747)와 Table S6이다. 6비트에서는 "mixed"였다. 8비트 동일 저장에서는 4-bit state + 4-bit direction memory가 0.36/0.46 ns, 8-bit state가 0.43/0.57 ns였다. 다만 저자들이 직접 "not as evidence that auxiliary bits are intrinsically more valuable than state bits"라고 단서를 단다. 원인은 4비트로 학습된 GRU의 interface 호환성이다. basis에서 언급한 Table S3은 parity 표가 아니라 state diagnostics 표다(l.613-615).
   - "EF + Gramian ≤ 5 bits": 우리 노트(recent/20260801_20261011.md:41)의 제안일 뿐 출판된 주장이 아니다.
   - 따라서 "기존 EF 이득은 회계 착시"라는 서술은 허수아비를 친다. 실제로 착시였던 것은 우리 idea 2 보고서의 config (d)다(judge/idea2.md l.13-19).
2. 예측("Weyl carry EF가 Weyl INT(b+b_r)를 넘지 못한다")은 nested 고정소수점에서 **정리**다. 실험으로 반증될 여지가 사실상 없다. 반증 가능한 내용은 nested가 깨지는 곳에만 남는다. 아래 "남는 열린 질문"을 참고.
3. "Weyl carry만이 이길 수 있다"는 문장은 틀렸다. b+b_r 비트 Markov write rule의 클래스는 균일 INT보다 넓다. 예: 2609.04490의 direction memory(부호 누적 카운터), 비균일/companded 격자. 이것들은 INT(b+b_r)와 동치가 아니다.

## 수학 스케치 (토이로 검증함)

**설정.** h_t = a h_{t−1} + u_t. 거친 격자는 Δ, 고운 격자는 δ = Δ/m, m = 2^{b_r}이다. threshold 수열 θ_t ∈ [0,1)에 대해 Q^θ_δ(x) = δ⌊x/δ + θ_t⌋이다(RTN은 θ ≡ ½, SR은 i.i.d. U, Weyl은 θ_t = {tφ + c}).

**명제 1 (two-limb 동일성).** a-가중 EF를 다음과 같이 정의한다.
- x_t = a(q_{t−1} + r_{t−1}) + u_t
- n_t = Q^θ_δ(x_t)/δ ∈ ℤ
- q_t = Δ⌊(n_t + m/2)/m⌋, r_t = n_tδ − q_t ∈ {−m/2, …, m/2−1}·δ (정확히 b_r비트)

그러면 q_t + r_t = Q^θ_δ(a(q_{t−1}+r_{t−1}) + u_t)이다. 이것은 같은 θ를 쓰는 단일 레지스터 INT(b+b_r)의 재귀와 같다. 따라서 모든 t에서 두 궤적은 같다.
- 증명: 분할 (q, r) ↔ n은 전단사이고, 재귀식이 n만의 함수이기 때문이다. ∎
- 함의 1: "EF + 4-bit carry vs INT8"은 같은 디코더다.
- 함의 2: RTN carry를 쓰면 fine-scale deadband |δ_t| < δ/2가 그대로 남는다. 2609.39185 Lemma 1을 δ에 적용한 것이다.

**명제 2 (표준 비가중 EF + 거친 readout).**
- 정의: x_t = a q_{t−1} + u_t + r_{t−1}, readout은 q_t다.
- s_t = q_t + r_t − h_t로 두면 s_t = a s_{t−1} + (1−a) r_{t−1} + ε_t이고, ε_t는 고운 반올림 오차다.
- readout 오차는 e_t = s_t − r_t다.
- 따라서 e_t = (단일 고운 레지스터와 같은 ε 필터링 항) + Σ_k a^k(1−a) r_{t−1−k} − r_t다.
- 추가 항은 |·| ≤ Δ로 유계지만 일반적으로 상쇄되지 않는다. 그래서 고운 레지스터보다 나쁘다(토이 참조).
- carry가 정확(FP32)할 때만 a와 무관한 균일 상한 ~Δ를 얻는다. 이것은 2607.23390 Thm 8의 축약 특수형이다. 단, 그때 저장량은 b+32비트다.

**정리화할 수 있는 상한/하한.**
- (a) 포함관계: EF(b, b_r) ⊂ {b+b_r비트 상태만 쓰는 Markov write rule}. 따라서 "그 클래스의 최적 rule"을 이길 수 없다. 자명하다.
- (b) 그러나 "특정 rule(균일 INT + Weyl)을 이길 수 없다"는 명제 1(가중형)과 명제 2(비가중형, rms 기준 근사)로만 성립한다. 비균일 rule이나 카운터형 rule에는 일반 정리가 없다.

**토이 (64채널, T = 2×10⁴, Δ = 0.05, b_r = 4, 마지막 2000스텝, 3 seeds).** rms/Δ 기준이다.

| a | RTN INT(b+4) | Weyl INT(b+4) | EF 가중 RTN carry | EF 가중 Weyl carry | EF 비가중 RTN, q readout | EF 비가중 Weyl, q readout | INT(b) RTN | EF exact(FP32) carry |
|---|---|---|---|---|---|---|---|---|
| 0.9 | 0.042 | 0.045 | 0.042 (동일) | 0.045 (동일) | 0.208 | 0.209 | 0.089 | 0.207 |
| 0.99 | 0.131 | 0.128 | 0.131 (동일) | 0.128 (동일) | 0.369 | 0.367 | 0.596 | 0.350 |
| 0.999 | 0.41–0.47 | 0.38–0.43 | 동일 | 동일 | 0.51–0.55 | 0.48–0.51 | 3.42 | 0.29 |

- 가중형 EF는 세 a, 세 seed 모두에서 고운 단일 레지스터와 소수점 끝자리까지 같다(명제 1 확인).
- **구현 함정(새 관찰, 사소함).** "먼저 Q_Δ, 그다음 잔차를 Q_δ로 반올림하고 b_r비트로 포화" 방식(sim.py)은 r = +Δ/2 타이를 클리핑한다. 이 체계적 편향이 1/(1−a)로 누적된다.
  - a = 0.999에서 rms 3.6–3.8Δ로, INT(b) RTN(3.4Δ)보다 나쁘다.
  - 실제 커널에서 EF가 "안 먹히는" 원인일 수 있다. 2607.23390이 overflow semantics를 강조하는 것과 같은 맥락이다.

## 남는 열린 질문 (실험할 가치가 있는 부분)

nested 고정소수점이 깨질 때만 equal-bit에서 차이가 날 수 있다.
1. **블록 스케일 분리.** carry가 자기 블록 스케일(잔차 블록 max)을 가지면 고운 격자가 적응적이 된다. 단, 스케일 바이트도 회계에 넣어야 한다.
2. **시간 가변 스케일.** 매 스텝 스케일을 재계산하면 시간축에서 격자가 nested가 아니다(2609.39185 INT8 + FP32 block scale 설정).
3. **FP limb.** FP8+FP8 double-word와 BF16/FP16을 비교한다. 지수 비트가 중복되므로 FP16(11 significand bits)보다 불리할 것으로 예상한다.
4. **direction memory류 비균일 rule.** 2609.04490 Table S6의 유일한 equal-bit 우위다. 단, 4비트로 학습된 GRU에서의 interface 효과다.

## 실험 스케치 (결정적, 1–3 GPU-day)

**모델과 프로토콜.**
- 모델: Mamba-2 2.7B, GDN 하이브리드 1종, 2609.39185와 같은 Granite/Falcon-H1 하이브리드 1종.
- 프로토콜: PG-19 8권, 2048토큰 FP prefill, 4096스텝 양자화 decode, BF16 상태 기준 KL.
- 채널 분할: a_t의 지수평균으로 slow(a > 0.99)와 fast로 나눈다.

**equal-byte arms** (상태 원소당 8비트, 스케일 바이트 포함):
- INT8 RTN, INT8 SR, INT8 Weyl
- INT4+INT4 EF 가중형(RTN carry, Weyl carry)
- INT4+INT4 EF 비가중·q readout
- INT4+INT4 naive saturating split
- INT4 + 4-bit direction memory
- INT4 + INT4 carry(별도 블록 스케일, 스케일 바이트 차감 후 equal-byte)
- FP8+FP8 vs BF16 (16비트 대조)

**단위 테스트.** 가중형 EF와 INT8의 로짓 차이 max = 0. 0이 아니면 구현 버그다.

**seed.** Weyl 위상 오프셋 c와 SR 난수를 5개씩 쓴다.

**반증 기준(원 가설 유지).** EF-Weyl carry(별도 스케일 포함 변형)가 Weyl INT8보다 slow 채널 KL에서 5-seed 평균 차이 > 2σ로 이기면 H4는 반증된다. 명제 1 때문에 가중형은 자동으로 동률이다. 따라서 정보가 있는 반증은 변형 1–3(블록 스케일, 시간 가변 스케일, FP limb)에서만 나온다.

**예상.** 가중형은 동률이고, 비가중형·naive는 패배한다. 블록 스케일 분리형은 스케일 바이트를 넣으면 ±noise다.

## 가설 재진술 (날카롭게)

nested 고정소수점에서 a-가중 EF(b비트 상태 + b_r비트 carry)는 같은 threshold 수열을 쓰는 단일 INT(b+b_r) 레지스터와 경로별로 동일하다. 표준 비가중 EF + 거친 readout은 그보다 나쁘다. 따라서 equal-bit에서 EF/ΣΔ의 이득은 nested가 깨지는 경우에만 가능하다. 그런 경우는 별도 블록 스케일, 시간 가변 스케일, FP limb, 비균일 카운터형 write rule이다.
