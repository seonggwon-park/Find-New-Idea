# 새 아이디어 1 판정 실험 결과 (축소 대리 실험, 2026-10-11)

## 결론

기각. 축소 대리 실험에서 kill gate의 두 기각 기준과 종단 기준을 모두 넘지 못했다.

## 설정

- 원래 계획(Llama-3.1-8B·Qwen3-8B·Mistral-7B, 4–32K, GPU)은 이 환경(GPU 없음, CPU 4코어, RAM 15GB)에서 불가능했다. 대신 Qwen2.5-0.5B(24층, 쿼리 헤드 14, KV 헤드 2, head_dim 64)를 CPU fp32로 돌렸다.
- 데이터: wikitext-103 test를 이어 붙여 4096토큰 창으로 자름. 보정 창 4개(헤드 측정·선택), 평가 창 12개(겹치지 않음).
- 캐시 모형: 창마다 프리픽스 [0, 3584)를 캐시로 둔다. 프리필은 FP(프리픽스 행은 FP V를 본다)이므로 모든 층의 K/V가 FP에서 유도된다. 평가 블록 [3584, 4096)의 행만 캐시된 프리픽스 V를 본다. sink 4토큰은 FP, 평가 블록 자신의 V는 FP(잔차 창 역할).
- V 양자화: 토큰별·헤드별 비대칭 min-max(head_dim 전체), 2-bit. SD는 토큰 축 1차 오차 피드백 q_t = Q(v_t − u_{t−1}), carry는 영구 저장 0바이트.
- 지표: 헤드별 R = Σ(Δp)²/Σp², h = 원소 오차 분산비(SD/RTN), 실측 출력 오차비; 종단은 평가 블록 512토큰의 NLL과 FP 대비 KL.
- 스크립트: `scripts/new_ideas/idea01_killgate.py`. 원자료: `idea01_qwen05b_b2.json`(헤드별 336행 포함), 로그 `idea01_qwen05b_b2.log`. 실행 시간 3,712초.

- 선택 SD-2가 닫은 RTN-2→RTN-3 KL 격차: 평균 9.2%(창별 4–18%, 12개 창 모두 25% 미만). 기각 기준(25% 미만)에 해당한다.
- 선택 SD-2 대 RTN-2의 KL 차: 0.00091 ± 0.00012(대응 표본). 통계적으로는 유의한 개선이지만 크기가 1비트 추가 효과(0.0099)의 9%다.
- NLL 차(선택 SD-2 − RTN-2): −0.00088 ± 0.00084로 유의하지 않다.
- SD-2를 모든 헤드에 쓰면 12개 창 모두에서 KL이 RTN-2보다 나빴다.

## 왜 실패했나

1. **어텐션 행이 매끄럽지 않다.** 양자화 구간에서 R의 중앙값이 1.50이다(상한은 2). 이득 조건은 R < 1/h인데, h가 1이어도 대부분의 헤드가 이득을 못 본다. 합성 실험의 uniform·local·recency 헤드(R ≪ 1)는 이 모델의 실제 행에서 드물다.
2. **h가 합성 가정의 두 배다.** 실제 V는 토큰마다 스케일이 크게 달라, 큰 스케일 토큰의 carry가 다음 작은 스케일 토큰의 min-max 범위를 부풀린다. 균질 Gaussian V를 쓴 합성 실험에서는 이 효과가 나타나지 않았다.
3. **예측 법칙도 실측에서 약하다.** 합성 데이터의 log 상관 0.99와 달리 실제 데이터에서는 0.46이다. 백색 오차 가정이 실제 RTN 오차(토큰 간 상관)와 맞지 않는다.

carry를 스케일에 맞춰 재조정하면 h는 줄일 수 있겠지만, R 중앙값 1.5가 남는 한 이득 상한 자체가 작다. 이 방향은 더 파지 않는 것이 맞다.

## 한계

- 0.5B 모델 하나, 4K 문맥, wikitext 한 종류다. 보고서가 정한 판정 조건(8B, 32K, LongBench/RULER)과 다르다.
- 다만 실패 원인인 R은 어텐션 패턴의 성질이라, 규모가 커진다고 행이 매끄러워질 근거는 약하다. 더 긴 문맥에서 diffuse 헤드의 비중이 늘어날 가능성은 남아 있으며, 이것이 결과를 뒤집으려면 R < 1/h ≈ 0.43인 헤드가 RTN 오차의 상당 부분을 차지해야 한다.
